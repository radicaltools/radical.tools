## Steps

1. Write modelling-cut.json as a Markdown model folder
2. Call smart_layout { viewId: Modelling } through the MCP server on it
3. Open the same folder's document in Studio's Designer on Modelling (its first Smart Layout runs by itself)
4. Compare the view's positions

## What differs

```text
Expected: The same positions from both, as for views already laid out (Payments Domain, Core Banking: 0 differ)
Actual: MCP: '39 moves — line length 1567.7 → 10.0, empty room 210.1 → 1.8'; Studio: '23 moves — line length 241.0 → 5.8, empty room 83.4 → 1.6'. 13 of 15 positions differ; the domain Modelling is 1066x375 from MCP and 1034x383 from Studio. The same on the full copy of .radical/model
Seen: 2 of 2 (3 runs of the script, plus the full model once)
Where it probably comes from: apps/mcp/src/folderModel.ts smartLayout starts a view with no positions from the nodes' own places, where children lie outside their parents; Studio's setActiveView opens it on firstCanvasPositions through showCanvasPositions/placeUnplaced, which puts them back inside first (guess)
A test that would catch it: apps/mcp/src/folderModel.test.ts: a view per element with no positions, whose subject's children lie outside its frame in the model's places: smart_layout gives the positions runTidyLayout gives on the canvas Studio opens the view with (layoutInputForView after showCanvasPositions)
```

## Fixed (2026-11-15)

MCP smart_layout of a view never laid out starts from the canvas Studio opens, via the shared placeOnViewCanvas.

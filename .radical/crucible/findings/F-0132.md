## Steps

1. Shop folder (MCP-built, test results beside it), Inspector › Overview › Needs attention › Requirement without scenario
2. Take wallet payments › Add scenario, type 'Paying with a wallet', Create
3. Wait 10 s, switch to Designer, then back to the Inspector

## What differs

```text
Expected: The scenario stays in the model, is written to the folder and is drawn beside the requirement in Designer
Actual: After Create: 13 elements, finding gone, card 'Paying with a wallet'; 10 s later not in the folder; Designer: drawn 0, Quick Search 0 hits, Undo disabled; Inspector again: 12 elements, 'Take wallet payments' without a scenario again
Seen: 2 of 2
Where it probably comes from: guess: apps/studio/src/renderer/src/persistence/autosave.ts treats the Inspector as explore mode (no save; the parked Designer model __preModeLayout is restored on the way back), while components/inspector/fixes.ts startFix edits the store in the Inspector
A test that would catch it: apps/e2e/tests/studio/inspector.spec.ts: after Add scenario › Create, switch to Designer: the scenario is drawn on Specification and the folder's nodes/ holds it after the save
```

## Fixed (2026-11-15)

Add scenario / Add fitness function in the Inspector is now a Designer edit through editAsDesigner, saved and undone in one step.

## Steps

1. Sample model moved to a folder (OPFS), Requirements Traceability
2. An agent's Forge run (.state/forge-run.json, active); Forge button → Follow on the canvas
3. Double-click Four-eyes approval, pick another EARS type in its card (the focus stays on the drop-down)
4. The agent renames Event Bus (shown in Core Banking), with its agent-activity mark

## What differs

```text
Expected: Studio opens Core Banking, as it does without the choice (control)
Actual: 5 s after the write Studio still shows Requirements Traceability; following resumes only when the focus leaves the drop-down
Seen: 2 of 2 (control 1 of 1 follows)
Where it probably comes from: apps/studio/src/renderer/src/persistence/followAgent.ts fieldHasFocus counts any SELECT or INPUT (checkboxes too) as a field typed in
A test that would catch it: apps/studio/tests/followAgent.test.ts: with a focused <select> (or checkbox), an outside edit is followed at once; with a focused text input it waits (F-0131)
```

## Decision (2026-11-15)

Following the agent waits only while the focus is in a field typed in (a text input, a textarea, editable text); a drop-down or a checkbox with the focus does not hold it back. To be written into the model's requirement on the branch that fixes it.

## Fixed (2026-11-15)

Following the agent waits only on a field typed in (the shared isTypedField), not on a drop-down, checkbox or button with the focus.

## Steps

1. Sample, Core Banking: select FX Engine, Alt-drag onto Accounts Service's 'uses' pill
2. Open milestone v3, Alt-drag FX Engine onto Accounts Service's 'inside' pill
3. Propagate to later milestones, back to Current (or the other order: nest live, connect in v3)

## What differs

```text
Expected: As the same nest made in the live model (mode live): the relation goes, with a notice; nothing Studio refuses ends up in the live model or later milestones
Actual: Live: comp-fx parent ctn-accounts and relation comp-fx -> ctn-accounts (interacts) kept; drawn 0 of 1 on Core Banking; Studio then offers no 'uses' there (0 pills). Mode connect: the same live result, v3/v4 get the relation. Mode live: relation removed
Seen: 3 of 3 (propagate), 2 of 2 (connect)
Where it probably comes from: guess: packages/ui/src/store/diagramStore.ts commitMilestoneChanges applyDiff copies addedRels and parentId updates without relationsToNewHolders / relationRefusal
A test that would catch it: packages/ui/tests/milestonePropagate.test.ts: after Propagate of a nest (and of a relation) in either order, live and later milestones hold no structural relation between an element and its ancestor
```

## Fixed (2026-10-26)

Propagate checks each later model and the live model for the relations it brings in (relationsRefusedHere) and leaves out, with a notice, those that model refuses.

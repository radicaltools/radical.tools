## Steps

1. C4 Shop folder; MCP create_milestone v1, then delete_node Storefront
2. Designer on Shop → Viewer → Milestones › v1
3. Models → Import from Hub… → Authentication → Add to Model: scope shows Storefront ticked, Suggested
4. Add to model

## What differs

```text
Expected: The wizard offers only elements of the model the import goes into (live), or the import refuses or says that Storefront is not in the live model
Actual: Studio switches to Designer and saves 25 elements (5 + 20) with 0 constrains relations and no notice; the same import with Viewer on the live model saves 4+ constrains → Storefront
Seen: 2 of 2
Where it probably comes from: guess: HubImportModal/ConcernWizard take elementIds from Viewer's store (the milestone); editAsDesigner switches to Designer's live model and importConcernPackIntoDiagram drops unknown ids (elementIds.map(id => store.c4Nodes[id]).filter(Boolean)); Presenter with a milestone-linked slide likely the same
A test that would catch it: apps/e2e/tests/studio/hub-import.spec.ts: Viewer on a milestone holding an element deleted since: the concern wizard does not offer it (or Add to model refuses with a notice); never a saved ADR with no constrains
```

## Fixed (2026-11-15)

The concern wizard offers and suggests the elements of the model the import goes into (Designer's parked model, not the milestone Viewer shows), and the import refuses an element that model does not have instead of dropping it silently.

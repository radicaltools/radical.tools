## Steps

1. New model; scenarios Pays and Refunds
2. .radical/radical.json binds 'tests/pay.test.ts > checkout > pays by card' to both
3. set_verification Pays tests ['tests/pay.test.ts › checkout › pays by card']
4. radical verify Refunds --test 'tests/pay.test.ts › checkout › pays by card'
5. Read .radical/radical.json

## What differs

```text
Expected: One test bound to Pays, as to Refunds (since F-0113 both forms are the same test)
Actual: Pays binds 2: ['… > checkout > pays by card', '… › checkout › pays by card'] and set_verification says 'checked by 2 test(s)'; Refunds binds 1
Seen: 2 of 2
Where it probably comes from: apps/mcp/src/folderModel.ts verification(): new Set([...bound, ...adds.map(canonicalTestId)]) does not canonicalise the bound ids; apps/cli/src/verify.ts compares with canonicalTestId
A test that would catch it: apps/mcp/src/folderModel.test.ts › test bindings: with 'f > d > t' bound, set_verification tests ['f › d › t'] leaves one test bound
```

## Fixed (2026-11-15)

Set_verification binds each test once however the file writes it (shared rebindTests with radical verify), and the check reads a duplicated binding once.

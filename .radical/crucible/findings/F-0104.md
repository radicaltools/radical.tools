## Steps

1. Sample as a folder; agent: create_milestone 'M', delete_node the Payment lifecycle state machine, delete_node ctn-fraud
2. Studio: v3 on Core Banking draws Fraud Detection; Presenter, M, State machines, Payment lifecycle, Add slide
3. Agent: create_presentation slide {viewId view-core, milestone snap-v3, focus [ctn-fraud]}
4. Agent: create_presentation slide {viewId view-payment-lifecycle, milestone M}; update_presentation focus on a state on Studio's slide 13
5. radical check on the folder

## What differs

```text
Expected: The agent can show and focus on what Studio draws in the milestone, and radical check accepts the slide Studio made
Actual: 'slide 1 focuses on node(s) not in view "Core Banking": Fraud Detection (ctn-fraud)'; 'slide 1 has unknown viewId "view-payment-lifecycle"'; 'slide 13 cannot focus on elements: without viewId it shows the All elements table' (the slide has viewId view-payment-lifecycle); radical check: warning 'Slide "Slide 13" … shows view view-payment-lifecycle, which the model does not have'
Seen: 2 of 2
Where it probably comes from: guess: packages/common/src/ai/tools/presentationTools.ts parseSlides/parseFocus judge the view by the live views instead of the slide's milestone's views (DiagramSnapshot.views); packages/common/src/check/index.ts staleReferences checks slide.viewId against the live view ids only
A test that would catch it: packages/common/tests (presentation tools): with a milestone holding an own copy of a view that lists an element deleted live, and a milestone-only view, create_presentation with that milestone and focus on the element succeeds, and checkModel reports no stale slide
```

## Fixed (2026-10-26)

The MCP presentation tools and radical check judge a milestone's slide by that milestone's views.

## Steps

1. New model folder; forge_start (layers), forge_clarify + forge_generate requirements, add_node requirement 'Pay by card', forge_complete_stage requirements
2. forge_clarify + forge_generate domain (optionally forge_propose_refinement adding a requirement)
3. forge_finish: accepted, says 'Domain model: begun but not completed'
4. add_node system 'Shop'; update_node / delete_node the requirement
5. Read .state/forge-run.json

## What differs

```text
Expected: A finished run guards nothing: the model tools work again (or forge_finish refuses while a stage is open or a proposal waits, as forge_complete_stage does); forge-run.json shows no stage generating or asking in a finished run
Actual: forge_finish accepted in both cases; afterwards 3 of 3 writes refused ('add_node: a system belongs to an earlier stage…', 'update_node: "Pay by card" belongs to an earlier stage…', 'delete_node: … a Forge stage never deletes one'; with a proposal: all 3 'proposal p1 waits for the user's answer'); forge-run.json: state finished, domain {status: generating} / {status: generating, asking: true}
Seen: 3 of 3
Where it probably comes from: apps/mcp/src/forge.ts: Forge.guard() checks only that a run exists, not run.finished; finish() neither closes the open stage nor refuses; status() returns 'generating' before it looks at finished (guess)
A test that would catch it: apps/mcp/src/forge.test.ts: generate a stage (and propose a refinement), forge_finish, then add_node/update_node succeed (or the finish is refused), and status() shows no stage generating/asking in a finished run
```

## Fixed (2026-11-15)

Forge_finish refuses while a stage is open or a proposal waits (as forge_complete_stage does), so a finished run guards no write and shows no stage generating or asking; a stage generated afterwards reopens the run, and the guard's add_node message names the stage the type belongs to, earlier or later.

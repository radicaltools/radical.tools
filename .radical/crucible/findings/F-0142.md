## Steps

1. Open the repository's model x4 as a folder, Designer, All elements, double-click 'Need is not a requirement' to open its card
2. Click at the end of Name and type ' abcdefghijklmnopqrstuvwxyz0123456789' (60 ms a key)
3. While typing, another program rewrites the file of a different element (its label changed)
4. Tab

## What differs

```text
Expected: Name 'Need is not a requirement abcdefghijklmnopqrstuvwxyz0123456789', and the other element's outside rename shown too
Actual: 'Need is not a requirement abcdefghijpqrstuvwxyz0123456789' (5 lost) and '...abcdefghijqrstuvwxyz...' (6 lost) at x4; 'x' lost 3 of 3 at x1; typing right after reopening from the cache with an outside change lost ' ', ' S', ' S' (3 of 3, e13.mjs)
Seen: 2 of 2 (5 of 5 with the variants)
Where it probably comes from: apps/studio/src/renderer/src/persistence/autosave.ts loadActive: `ours: buildPersistData()` is taken before `documents.loadDocument(id).then(...)`; edits that reach the store during that read are not in it and loadDiagram replaces them (also on the path without unsaved edits, store.loadDiagram(data)); the read takes longer on a large folder (guess)
A test that would catch it: apps/e2e/tests/studio/folders.spec.ts: type a name in the card key by key while folder.write changes another element; after Tab the Name is exactly what was typed and the outside change is shown; or a unit test of loadActive with a slow loadDocument and an updateNode during it
```

## Fixed (2026-11-15)

LoadActive now takes the user's edits when the folder read is back, so what was typed during the read is merged, not replaced.

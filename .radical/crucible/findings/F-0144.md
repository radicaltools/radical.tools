## Steps

1. Repository with scenario 'Pays by card', tests/pay.spec.ts and a Playwright JSON report where 'pay › takes a card' passed
2. radical verify "Pays by card" --test "tests/pay.spec.ts:2:3 › pay › takes a card" (as the list reporter prints it; also with '[chromium] › ' in front)
3. radical check --report playwright.json
4. radical check --trace pay

## What differs

```text
Expected: The test is found and passes (Scenarios: 1 passed), as with 'tests/pay.spec.ts › pay › takes a card'; or verify says the form to use
Actual: Both printed forms: verify exit 0 and stored as given; check: test-not-run warning, Scenarios 1 not-run, Requirements 1 unverified; trace not-run. The bare form: 1 passed, 1 verified (Playwright 1.63 formatTestTitle prints [project] › file:line:col › titles)
Seen: 2 of 2
Where it probably comes from: packages/common/src/check/reports.ts canonicalTestId / testIdParts keep a '[project]' part and a ':line:col' suffix on the file (guess); apps/cli/src/verify.ts and MCP set_verification store it
A test that would catch it: packages/common/tests/checkReports.test.ts: an id 'tests/a.spec.ts:2:3 › d › t' and '[chromium] › tests/a.spec.ts:2:3 › d › t' find the Playwright JSON case as 'tests/a.spec.ts › d › t' does (or canonicalTestId drops both); apps/cli/src/verify.test.ts: verify keeps the bare form
```

## Fixed (2026-11-15)

Test ids drop the project Playwright or Vitest prints before the file and the :line:col after it, so a test bound as a runner prints it is found in the report.

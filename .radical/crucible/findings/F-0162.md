## Steps

1. A view listing Shop, API and API's 1,100 components, with API folded in the view (collapsedNodeIds)
2. Open it in Designer

## What differs

```text
Expected: Either the canvas draws the 2 elements it would draw, or the manual says folded contents count
Actual: Notice 'API folded shows 1,102 elements', 0 elements drawn; the same view with 900 components draws 2 elements
Seen: 2 of 2
Where it probably comes from: packages/common/src/viewPipeline.ts canvasCount counts viewShownNodes, ignoring the view's folds
A test that would catch it: packages/ui/tests/oversizedCanvas.test.ts: a view whose 1,001 listed elements lie in a container folded in the view is (or is not, as decided) oversized
```

## Decision (2026-11-15)

The canvas limit counts what the canvas draws: the contents of a container folded in the view do not count, so folding a large container lets the view be drawn. To be written into the model's requirement on the branch that fixes it.

## Fixed (2026-11-15)

The canvas limit counts what the canvas draws, so the contents of a container folded in the view (or on the model and not opened there) no longer count, in Studio's notice and the MCP server's refusals alike; an exploration still counts every element it lists.

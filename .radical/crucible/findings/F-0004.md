## Steps

1. git repo with src/fix.mjs changed and src/helper.mjs new (untracked)
2. radical harden --gate --test "tests/t.mjs › x" with a runner for tests/
3. press Ctrl+C (SIGINT to the process group) while step 1 'without the fix' runs

## What differs

```text
Expected: src/fix.mjs and src/helper.mjs as they were before the gate
Actual: src/fix.mjs is the base version (git status clean), src/helper.mjs is deleted; the only copies are in $TMPDIR/radical-harden-XXXX and nothing says so; the same with SIGTERM
Seen: 5 of 5
Where it probably comes from: apps/cli/src/harden.ts setBack: files are put back in a finally, which does not run when Node exits on a signal (no SIGINT/SIGTERM handler)
A test that would catch it: apps/cli/src/harden.test.ts: spawn the gate on a temp repo with a slow runner, send SIGINT once 'Gate for' prints, assert the changed and new files are back
```

## Fixed

2026-10-22 (fix round of round 170–175, branch fix/r170): An interrupted radical harden --gate (Ctrl+C, kill or a closed terminal) stops its tests, puts the changed and new files back and exits 2, naming the folder of copies if one cannot be put back.
Test: apps/cli/src/harden.test.ts › puts the fix back when it is interrupted (SIGINT to the process group, as Ctrl+C does)

## What differs

```text
Expected: A new part of Payment (Kind entity, part-of Payment) or no such + row; a new element passes what the view filter says it is
Actual: table: 283 -> 283 elements, notice 'Relation not allowed: "New Entity" is an aggregate root, which is part of no other' (+ row offered under all 8 entities); wiki: Payment Fee kind aggregate-root with no part-of, listed at the top, no notice; any (A system's containers chain): refused 'Core Banking Platform holds Statements Service'; anywiki: container inside Core Banking with no relation, no notice; parts: kind "" (card —) listed among parts, Domain model draws AGGREGATE ROOT
Seen: 2 of 2 (each mode)
Where it probably comes from: guess: packages/common/src/viewPipeline.ts addChoices/meetFilters do not set kind entity for a part-of link nor check relationRefusal for a new element; WikiView.tsx writeElements -> addNodes drops the refused link silently; propertyValues treats '' as unset while relationRules.kindOf and C4Nodes treat it as aggregate-root
A test that would catch it: packages/common/tests/viewPipeline.test.ts: every addChoices choice with a link on the fintech sample, made new with its properties, passes checkAddRelation; apps/e2e/tests/studio/view-pipeline.spec.ts: '+ Entity · made up of' under Payment adds a part linked part-of, and the wiki writing line does too
```

## Fixed (2026-10-26)

Table and wiki offer a new element under another only with a link the model accepts and the values it needs (a part is Kind entity), addNodes refuses a refused link with its reason, and a choice stored as '' reads as its type's default everywhere.

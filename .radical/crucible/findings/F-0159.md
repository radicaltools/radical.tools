## Steps

1. A folder model: system Shop, container API with 1,100 components, container Small with 2; a view 'Components' of the viewpoint 'Components of a container' (a group of views per element, made with the MCP server's create_view)
2. Open the view API in Designer: the notice 'API shows 1,101 elements. A canvas draws up to 1,000. Show the view as a table…'
3. Click Show as a table
4. Click Edit the filter

## What differs

```text
Expected: The notice offers only what works for a view per element (or says to change the group's viewpoint), or Show as a table shows it as a table
Actual: Show as a table: nothing happens (notice still shown, no undo step); Edit the filter: the properties open with the filter read-only (the group's) and no View type section; in Viewer the text says to open it in Designer to show it as a table, which Designer cannot do
Seen: 2 of 2
Where it probably comes from: packages/ui/src/components/LargeCanvasNotice.tsx offers both buttons for any view; packages/ui/src/store/diagramStore.ts setViewKind returns when setByGroup(view) (partOf or group); RightPanel ViewPipelinePanel readOnly for ofGroup
A test that would catch it: packages/ui/tests/oversizedCanvas.test.ts or apps/e2e/tests/studio/large-canvas.spec.ts: a view per element over 1,000 shows a notice without a dead Show as a table / Edit the filter (or with a working way on)
```

## Fixed (2026-11-15)

A view per element larger than a canvas now says its group's viewpoint sets its view type and filter and offers Edit the viewpoint, which opens the Metamodel editor on that viewpoint, instead of the dead Show as a table and Edit the filter (Viewer's text likewise).

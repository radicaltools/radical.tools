## Steps

1. New model folder in a git repository; add_node system Shop, container API in it, scenario Pays
2. set_implementation API paths [apps/api]; set_verification Pays tests [apps/api/pay.test.ts › pays]
3. delete_node API; delete_node Pays
4. get_implementation / get_verification: both entries marked unknown; radical check: 2 repository-mapping warnings
5. set_implementation {id: <API id>, remove: true} and set_verification {id: <Pays id>, remove: true}

## What differs

```text
Expected: delete_node takes the element's entries out of .radical/radical.json, or at least remove: true takes out an entry whose element is gone
Actual: Both remove calls refused ('set_implementation: no element e7a4… in the model', 'set_verification: no element ea78… in the model'); radical.json keeps 1 implements and 1 verifies entry; radical check warns twice; radical implement --remove cannot name the id either
Seen: 3 of 3
Where it probably comes from: apps/mcp/src/folderModel.ts implementation() and verification(): the 'no element' guard runs before remove; delete_node never touches radical.json (guess: also apps/cli/src/implement.ts openElement)
A test that would catch it: apps/mcp/src/folderModel.test.ts: delete a mapped container and a bound scenario, then set_implementation/set_verification remove: true on their ids succeed and the file's lists are empty (or delete_node removes the entries)
```

## Fixed (2026-11-15)

Delete_node takes the deleted elements' entries out of .radical/radical.json, and remove: true (MCP) and --remove (CLI, by id or name) take out an entry whose element is gone; Studio's undoable delete still leaves them, and the check warns.

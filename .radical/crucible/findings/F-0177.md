## Steps

1. Sample model moved to a folder (OPFS), Core Banking
2. Double-click Accounts DB, type ' abc' into Name
3. Another program deletes Event Bus's file (its 19 relations stay in relations.json); Studio reloads
4. Tab

## What differs

```text
Expected: No change of the user's reported as dropped (at most: Event Bus was deleted outside Studio)
Actual: 'Your edits were merged with a change made outside Studio: Event Bus was deleted outside Studio; the relation Event Bus → Message sent with its change made to it in Studio was dropped; ... and 14 more' (19 relations blamed on Studio; the user changed none). No notice without the unsaved edit, and a correct one when relations.json loses the relations too
Seen: 3 of 3
Where it probably comes from: packages/common/src/modelMerge.ts dropStrays: `by = ours has the element ? 'ours' : 'theirs'` reports a relation held unchanged by base, ours and theirs as drawn by the side that kept the element
A test that would catch it: packages/common/tests/modelMerge.test.ts: base with X and X→Y, ours renames another node, theirs drops X but keeps X→Y: `dropped` has no 'the relation … made to it' entry by ours, merged has no relation to X
```

## Fixed (2026-11-15)

The merge reports a relation to an element deleted on the other side only when the side that kept the element drew or changed it, so relations left in relations.json by a hand-deleted file no longer appear as Studio's lost changes.

## Steps

1. bookstore fixture, Designer, Containers view
2. Click Payment Provider, press Delete: 'Delete 1 element and 1 relation?'
3. Press Cmd/Ctrl+P, type System Context, Enter
4. Click 'Hide from current view'
5. (also: Delete on Orders DB, then F5; or a drag, Delete, then Ctrl+Z)

## What differs

```text
Expected: While the prompt asks, Cmd/Ctrl+P, F5, Ctrl+Z, Cmd+= and Alt+Left do nothing behind it; Hide hides from Containers, where Delete was pressed
Actual: The view behind switches to v-context with the prompt still open, and Hide takes Payment Provider out of System Context (3 to 2 elements) while Containers keeps it. F5 starts the presentation (.mode-presenting) with the prompt over slide 1, and Remove from model there deletes nothing. Ctrl+Z moves Orders DB back from (820,560) to (640,425) behind the prompt. Cmd+= zooms and Alt+Left goes back behind it too
Seen: 3 of 3
Where it probably comes from: packages/ui/src/components/DeleteConfirmDialog.tsx: its backdrop has no role=dialog aria-modal, so keysHere.ts modalDialogOpen() and dialogKeys.ts keysTakenByDialog() (Toolbar F5/undo/zoom, QuickSearch, NavHistory) do not see it; diagramStore.ts startPresentation clears relationTypeChoice and exploreMenuFor but not pendingDelete
A test that would catch it: apps/e2e/tests/studio/editing.spec.ts: bookstore Containers, select Payment Provider, Delete; press Ctrl/Cmd+P + 'System Context' + Enter, F5, Ctrl+Z: the URL stays on v-containers, no .mode-presenting, a drag made before is not undone; Hide from current view removes payments from Containers' nodeIds only
```

## Fixed (2026-11-15)

The Delete prompt is a modal dialog to the one key rule (keysTakenElsewhere), so ⌘P, F5, Ctrl+Z, ⌘+ and Alt+← do nothing behind it, and starting a presentation clears it.

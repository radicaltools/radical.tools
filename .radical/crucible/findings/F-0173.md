## Steps

1. bookstore fixture, an AI provider set up, Designer, Containers view
2. Click Orders DB
3. Open Radical Forge (toolbar), click its Description tab
4. Press Delete
5. Close Forge

## What differs

```text
Expected: Delete does nothing to the canvas while the focus is in Forge, as F5 does nothing there
Actual: 'Delete 1 element and 1 relation?' opens under the Forge panel and is there when Forge is closed; F5 in the same state starts no presentation (0 of 1)
Seen: 3 of 3
Where it probably comes from: packages/ui/src/components/keysHere.ts canvasKeysOff checks modalDialogOpen() and fields only, while apps/studio/.../dialogKeys.ts keysTakenByDialog also counts focus inside a [role=dialog] (Forge, the agent run panels); used by useDeleteKey in packages/ui/src/components/Canvas.tsx
A test that would catch it: apps/e2e/tests/studio/editing.spec.ts: AI settings seeded, select Orders DB, open Radical Forge, click its Description tab, press Delete: no .milestone-modal-title starting 'Delete'; or a unit test: canvasKeysOff is true for a target inside [role=dialog]
```

## Fixed (2026-11-15)

A key pressed in any dialog or menu, Radical Forge included, is not the canvas's, so Delete there opens no prompt.

## Steps

1. Bookstore (Radical metamodel) moved to a folder; an active agent Assay run in .state/assay-run.json; AI provider scripted in the page
2. Open Radical Forge, type a description, Layer canvases, Start →, Generate requirements
3. Forge waits on Requirements with Continue →
4. Click the Assay button (the Assay panel replaces Forge), Escape
5. Click Open Radical Forge

## What differs

```text
Expected: Forge comes back on Requirements with Continue →, or the Assay click is refused with the notice shown while Forge generates
Actual: Forge reopens on Description, description empty, no stage done, Start → (before: Requirements active, Description done, Regenerate / Continue →); the generated requirements stay in the model but the run cannot be continued. Before #369 the Assay click did nothing and Forge kept its run
Seen: 2 of 2
Where it probably comes from: apps/studio/src/renderer/src/components/Toolbar.tsx showRunPanel guards only forgeBusy; RadicalForgeModal's reset effect on open (guess)
A test that would catch it: apps/e2e/tests/studio/folders.spec.ts (or forge.spec.ts): scripted provider, generate one stage, click .qs-assay-toggle, close it, open Forge again: Requirements step active and Continue → present
```

## Fixed (2026-11-15)

Radical Forge put aside for another run panel keeps its run and comes back on the stage it was at; closing it still starts afresh.

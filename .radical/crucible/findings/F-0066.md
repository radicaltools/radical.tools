## Steps

1. Sample, Designer, Core Banking: select Payments Service, Delete, Remove from model
2. Milestones: open v3 – Full Platform
3. Views: Folder properties on Logical, Rename folder, 'Architecture'
4. View properties on Core Banking, Rename view, 'Core Banking X'
5. Milestones: Current (live)

## What differs

```text
Expected: One folder Architecture with all 8 views, Core Banking named 'Core Banking X', in the list and in the saved document
Actual: In v3 the list shows Architecture 8 and 'Core Banking X', but the saved document already has Architecture = [System Context, Domain realisation] and Logical = the 6 views v3 keeps its own way; back on the current model the list is Conceptual 14, Architecture 2, Logical 6, Governance 4, Concerns 8 and view-core is named 'Core Banking'
Seen: 2 of 2
Where it probably comes from: guess: packages/ui/src/store/diagramStore.ts showMilestoneViews parks the live copies in liveBackup.views and unparkLiveViews writes them back whole; renameView, renameViewFolder and setViewFolder change only the copy shown, and the save writes the parked copy
A test that would catch it: packages/ui/tests: with a milestone that has its own copy of view V in folder F shown, renameViewFolder(F, 'G') and renameView(V, 'X'), then discardMilestoneChanges(): every view of F is in G and V is named X, also in the saved document
```

## Fixed (2026-10-26)

Renames of views and folders made while a milestone is shown reach the live views parked under its own copies, so they are saved, put back on leaving and propagated (parkedAsShown).

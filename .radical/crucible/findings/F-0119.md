## Steps

1. Open the payments folder with orders fetched (bookstore fixture; its table v-table lists every element)
2. Views → orders › Element Table

## What differs

```text
Expected: 6 rows, orders' elements only, as the card counts
Actual: 8 rows: orders' 6 plus pay-sys (Payments) and pay-clerk (Clerk) of payments, with no origin chip
Seen: 3 of 3
Where it probably comes from: packages/common/src/viewPipeline.ts structureRows/runPipeline ignore view.originScope; only viewShownNodes applies it via scopedTo (guess; wiki/Warnier/matrix likely the same)
A test that would catch it: packages/common/tests: structureRows of a table view with originScope ['orders'] and empty nodeIds returns only elements with an orders origin; e2e in federation.spec.ts: orders' table has no tr.tv-row without .tv-origin
```

## Fixed (2026-11-15)

PipelineSource applies originScope, and the wiki and matrix of every element use viewShownNodes, so another model's table, wiki, Warnier view and matrix list only that model's elements.

## Steps

1. A folder model with a static view 'Every requirement' whose filter gives 3,000 requirements (Studio shows the notice, no Smart Layout button or command)
2. Through the MCP server: smart_layout {viewId: 'v-reqs'}
3. grid_nodes {viewId: 'v-reqs', nodeIds: [r0..r3], columns: 2}

## What differs

```text
Expected: Refused as Studio refuses it: the view has more elements than a canvas draws (1,000), with no file written
Actual: smart_layout done in 23.7 s / 24.4 s: 'nothing left to tidy; the view keeps its places. Changed: views.json', places kept for the view 0 -> 3,000; grid_nodes done in 0.2 s; 10.3 s for 1,001 elements
Seen: 2 of 2
Where it probably comes from: packages/common/src/ai/tools/layoutTools.ts noCanvasLayout/canvasFor and apps/mcp/src/folderModel.ts smart_layout (~line 966) refuse only non-static kinds; no CANVAS_MAX_ELEMENTS check (guess)
A test that would catch it: apps/mcp/src/folderModel.test.ts: smart_layout, align_nodes and grid_nodes on a static view whose filter gives 1,001 elements return an error naming the 1,000 limit and change no file
```

## Fixed (2026-11-15)

Smart_layout, align_nodes, grid_nodes and forge_arrange refuse a view that shows more than 1,000 elements, naming the limit and writing nothing, through the same canvasOverflow check Studio's notice uses.

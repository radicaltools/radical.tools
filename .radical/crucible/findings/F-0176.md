## Steps

1. Sample model moved to a folder (OPFS), Requirements Register
2. Double-click 'Four-eyes approval', click the action slot of its EARS sentence in the card, type ' abc'
3. Another program renames a different element (Corporate treasurer feedback) in its file; Studio reloads the folder
4. Type ' def', Enter

## What differs

```text
Expected: The slot stays open with '...before the batch is submitted abc def', and that is saved
Actual: The slot closes at the reload (focus on BODY); ' abc' is not saved, ' def' goes nowhere; saved action ends '...before the batch is submitted'. Card Name/Rationale, the wiki's EARS slot, table F2, Warnier F2 keep the text across the same reload
Seen: 3 of 3 (control 1 of 1 holds)
Where it probably comes from: packages/ui/src/components/RightPanel.tsx EarsSentencePreview: `const Slot = (...) => {...}` is declared inside the render, so each re-render (the reload replaces c4Nodes) remounts every Slot and drops its editing state and draft; WikiView's EarsSlot is top-level and survives
A test that would catch it: apps/e2e/tests/studio/folders.spec.ts: open a requirement's card, click a sentence slot, type, folder.write renames another element, type more; the slot input is still focused with the whole text and the file has it after Enter
```

## Fixed (2026-11-15)

Each part of the EARS sentence in the card is a top-level component, so an outside reload no longer closes the part being typed in or loses its draft.

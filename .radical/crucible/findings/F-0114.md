## Steps

1. Central model repository: check.json requirement-without-scenario max 3, three such requirements, one on Web
2. Web repository: .radical/radical.json model.repo ../central, implements Web; the model cloned at .radical/model
3. radical check --ratchet in the Web repository
4. Copy the resulting check.json to the central repository; radical check there

## What differs

```text
Expected: Baseline stays 3 (the model still has 3); the model's own check exits 0
Actual: Ratchet: requirement-without-scenario 3 → 1 written to .radical/model/check.json (git: M check.json); the central check exits 1 with 3 errors (3, max 1)
Seen: 2 of 2
Where it probably comes from: apps/cli/src/check.ts checkCommand: --ratchet runs ratchetConfig on the result of the judged part (repository.model) and writes the model's check.json
A test that would catch it: apps/cli/src/cli.test.ts: in a repository whose radical.json names model.repo, check --ratchet leaves check.json unchanged (or exits 2 saying why)
```

## Fixed (2026-11-15)

Check --ratchet in a repository that judges its part of a model kept elsewhere refuses (exit 2) to lower the model's check.json, and lowers only a config of the repository's own.

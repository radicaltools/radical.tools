## Steps

1. Orders (bookstore fixture) with a group of views per element of the C4 viewpoint 'Containers of a system' (group v-sysgroup with the view of Bookstore and of Payment Provider); payments depends on orders, fetched with radical federation fetch
2. Open → Folder… on payments, Designer, Landscape: views.json holds Landscape and Payments table
3. Drag a Software System from the palette onto the canvas
4. Read payments' views.json

## What differs

```text
Expected: views.json keeps Landscape and Payments table only; orders' group stays orders' and makes no view in payments
Actual: views.json gains 3 views: Payments, Bookstore, System, each partOf v-sysgroup (orders' group) in folder 'orders'; the group's card says 3 views; MCP add_node on the same folder writes Payments, Bookstore, Ledger the same way ('Smart Layout arranged the 3 new views per element')
Seen: 4 of 4
Where it probably comes from: packages/common/src/federation.ts otherModelView keeps viewpoint and drops partOf, and packages/common/src/model.ts isViewGroup/planViewGroups (from diagramStore _sync and ai/modelFacade) take a view with an origin for this model's group (guess)
A test that would catch it: packages/common/tests/federation.test.ts: withOtherModels with a federation file holding a group view (viewpoint with subject types) and its members, then syncViewGroups: no view added, none changed; apps/e2e/tests/studio/federation.spec.ts: add an element on a model with such a fetch, views.json has no view with partOf of another model's view
```

## Fixed (2026-11-15)

Another model's views keep their group, and the group and viewpoint syncs (Studio, MCP, Forge) leave views with an origin alone, so nothing of theirs makes a view in this model's folder.

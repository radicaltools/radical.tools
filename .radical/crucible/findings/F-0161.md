## Steps

1. A folder model: a need 'The brief' with 1,200 requirements deriving from it; view Brief shows the need alone
2. Designer, view Brief, double-click The brief, click Explore in its card: the + menu 'Add to The brief' opens
3. Press Escape

## What differs

```text
Expected: Esc closes the menu, as it does when a row can be added (10 requirements: focus on Show all, Esc closes)
Actual: Rows: Show all 1200 [off], Derives from 1200 [off], Show checked [off]; document.activeElement is BODY; after Escape the menu is still open
Seen: 2 of 2 (closes with 10 requirements)
Where it probably comes from: packages/ui/src/components/ExploreMenu.tsx: Esc only in the menu's onKeyDown; on open it focuses [role=menuitem]:not(:disabled), none here (guess: focus the menu itself, or listen for Esc on window)
A test that would catch it: apps/e2e/tests/studio/large-canvas.spec.ts: Explore from an element with 1,001 neighbours, every row disabled, Escape closes the menu
```

## Fixed (2026-11-15)

The + menu focuses itself when every row is off, so Esc closes it.

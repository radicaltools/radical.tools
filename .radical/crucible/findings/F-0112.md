## Steps

1. New model; forge_start with a description
2. forge_skip_stage [mockups, states] with a reason
3. forge_clarify requirements
4. forge_finish
5. Read .state/forge-run.json

## What differs

```text
Expected: forge_finish names as skipped only the stages left out with forge_skip_stage, and the rest as not run (or refuses to finish while stages are neither run nor skipped), as the run status does
Actual: forge_finish: 9 of 9 stages 'skipped' (2 with the reason, 7 without); forge-run.json: state finished, requirements clarifying, 6 pending, 2 skipped
Seen: 3 of 3
Where it probably comes from: apps/mcp/src/forge.ts Forge.finish() ('if (!state) return skipped') vs Forge.status(); forge.test.ts asserts '- Domain model: skipped' for a clarified stage, so possibly intended
A test that would catch it: apps/mcp/src/forge.test.ts: after skip of two stages and finish, the finish text and forge-run.json agree on which stages were skipped
```

## Decision (2026-11-15)

forge_finish names as skipped only the stages left out with forge_skip_stage (with their reason) and every other stage 'not run', as .state/forge-run.json and Studio's run status do. Finishing with stages not run stays allowed. To be written into the model's requirement on the branch that fixes it.

## Fixed (2026-11-15)

Forge_finish says "skipped (reason)" only for stages left out with forge_skip_stage and "not run" for the rest, and a finished run's status shows no stage as clarifying.

2. Smart Layout
3. Smart Layout again

## What differs

```text
Expected: Run 2: 'nothing left to tidy'
Actual: Run 1: 99 moves; run 2: '89 moves — empty room 2.7 → 2.3', 15 of 16 elements moved, starting with gathering elements without relations into the margin; run 3: nothing left. Engine alone: 99 / 89 / 0 steps; MCP smart_layout the same
Seen: 2 of 2 in Studio, engine and MCP too
Where it probably comes from: packages/layout/src/tidy/index.ts runTidyLayout closing passes (gather into the margin, MAX_PASSES): the margin gathering at the start of run 2 opens moves run 1 did not take (guess); sibling of F-0074
```

## Fixed (2026-10-26)

Tidy runs again on its own layout and takes what that run finds, until a run finds nothing (budget allowing), so the next Smart Layout finds nothing.

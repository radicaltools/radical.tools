## Steps

1. Repository folder (.radical/model with scenario Pays, .radical/radical.json binding 'tests/pay.test.ts › pays by card', test results) opened in Studio by the repository
2. Inspector → Settings: scenario-verifies-nothing → Error (a draft)
3. Meanwhile the agent: set_verification Pays tests ['tests/pay.test.ts › declines an expired card'] (radical.json now binds 2)
4. Within the 3-second poll: Save
5. Read .radical/radical.json

## What differs

```text
Expected: Save changes only the repository settings it edits (or none), over the file as it is: Pays keeps both tests
Actual: After Save Pays binds 1 test (the agent's 'declines an expired card' is gone), with no message; the Implementation tab says 1/1 named tests; check.json got the severity
Seen: 4 of 4
Where it probably comes from: apps/studio/src/renderer/src/persistence/inspector.ts saveCheckConfig(): next = { ...useDiagramStore.getState().repository, … } (the 3 s poll's copy) is written whole, instead of re-reading the file before writing (or writing only when tests/ci changed)
A test that would catch it: apps/e2e/tests/studio/repository-mapping.spec.ts: open the repository, draft a Settings change, write radical.json with a second binding behind Studio's back, Save at once: radical.json still has both tests
```

## Fixed (2026-11-15)

Settings' Save reads check.json and radical.json again and writes only what the draft changed over them, so an agent's binding made meanwhile stays.

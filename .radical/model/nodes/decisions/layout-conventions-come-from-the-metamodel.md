label: "Layout conventions come from the metamodel"
alternatives: "A fixed table of built-in ids inside the layout package (no custom types, two places to keep in step). An engine per view kind (state machine, requirements, screens: three algorithms, more code, no shared criteria). Roles read from the graph alone (degree, leaves): it cannot tell a start from an end, nor a store from a note."
consequences: "Views of every kind are tidied by their notation's conventions with one engine; a custom type gets a role by setting it. A hint changed in the metamodel changes layouts. Tidy needs the metamodel: Studio and the MCP server pass it, and without one the Radical preset's hints apply."
context: "Tidy knew five roles from a fixed list of built-in type ids (a person, a database, the governance notes) and took every relation for a flow from its source down to its target. A state machine's initial pseudostate and final state, a queue between its producer and consumer, a need above the requirements derived from it, an aggregate root above its parts, screens read from left to right: none of it reached the layout, and the criterion against lines running upward punished a requirements chain drawn the right way up (the requirement points at its need). A custom type got no role at all. Kieffer et al. 2013 (SBGN) and the BPMN layout work encode a notation's conventions as which elements go where and which edges set the direction."
date: "2026-10-24"
decision: "Each node type carries a layout hint in the metamodel: a role (actor, store, note, start, end, broker, screen or element), the side the role is placed on, and roles by a property's value (a pseudostate of kind initial is a start, a state of kind final an end). Each relation type carries a flow: forward, reverse or side, with its axis. The built-in presets set them for C4, DDD, governance, state machines, processes and mockups; a document whose metamodel copy lacks a hint gets the preset's for a built-in id; the metamodel editor and the MCP upsert tools edit them. Tidy reads roles and flows from the metamodel it is given: the cost against the flow, the misplaced roles and the moves (actor up, start up, end down, outside system out, store right, note left, broker between its two sides, screens in a row) follow the hints, and a side relation sets no direction."
status: "accepted"

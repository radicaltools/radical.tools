label: "Assay reads code through syntax trees"
alternatives: "1. Keep regular expressions and fix each case (the cost grows with every rule, and new stacks start low). 2. Native tree-sitter for Node (fast and synchronous, but a native module in a CLI that ships with no runtime dependency, built per platform). 3. ast-grep or Semgrep rules (structural patterns over the same trees; a native module, and Semgrep's rule registry is licensed apart). 4. CodeQL or language servers (types and values across files, but they build the code and CodeQL's licence bars commercial use). 5. ANTLR grammars per language (one runtime in TypeScript, but grammars of uneven quality and no shared query language)."
consequences: "Structure no longer depends on how a file is laid out: nesting, comments, attributes in any order and the class a method is in come from the tree. The CLI and the MCP server ship the grammars as files beside their bundle (Java 0.4 MB, C# 5 MB, more with each language), and every entry point awaits prepareSyntax before reading. A language with no grammar in the package (Kotlin, Elixir, VB6) keeps its regular expressions until one is added. Types and values across files are still not known: a tree says what a line is, not what a variable holds."
context: "Assay's readers find routes, clients, SQL and ORM classes with regular expressions over a file's text. Six rounds of held-out repositories showed the cost: a regular expression sees neither nesting (Room's @Entity(…ForeignKey(…)…) lost its table name), nor what a line is inside (an ASP.NET Core action lost its class's [Route] and [controller]; a Spring Feign interface's methods were read as the service's own routes, as agents running Assay reported three times), nor comments and strings without a separate pass each; every fix was a narrow rule for one repository, and on the first contact with a new stack calls were read at 29 % to 56 %. The maintainer, 2026-11-09, after the comparison (translated from Polish): \"ok. go on\"."
date: "2026-11-09"
decision: "Assay parses code with tree-sitter, run as WebAssembly (web-tree-sitter and the grammars of @vscode/tree-sitter-wasm, MIT): nothing native, nothing of the repository run, the same in the CLI, the MCP server and the tests. A reader asks the syntax tree for structure (a class's annotations and its methods', a string literal, a call) and keeps regular expressions for the inside of a literal (a URL, a connection string, an SQL statement). The grammars load once, asynchronously, before a repository is read (prepareSyntax); the readers stay synchronous. Readers move one at a time, routes first (Java and C#), each kept or bettered on the bench before the regular expressions it replaces are removed."
status: "accepted"

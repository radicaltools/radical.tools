label: "The model folder holds nothing of the repository"
alternatives: "Leaving adapter arguments in the measure: paths and tool options in the model, as tests were. Keeping the settings in check.json and reading them per repository: one file for two owners. Forbidding paths in descriptions: they explain the model to people; a warning keeps them true."
consequences: "A model folder copied into another repository, or shared by a central model, carries no paths or tool options of the one it came from. Each repository says in one place, .radical/, what it runs and keeps. A description may still name code: the check says when it no longer exists. Studio edits the moved settings only where it can write the repository's file (the desktop, or a browser that opened the repository)."
context: "With the elements' folders and the tests bound in .radical/radical.json, four things of the repository were still in the model folder. A fitness function's measure could hold an adapter's command line (playwright tests/studio/scale.spec.ts --cwd apps/e2e --env SCALE_MODEL=…). check.json held, beside the model's rules and goals, the repository's test file globs (test-unbound's include and exclude) and its CI artifact names. reviews.json held the reviews of manual fitness functions: evidence, as test results are, not model. And element descriptions named code paths that drift silently when the code moves (304 in this repository's model)."
date: "2026-11-02"
decision: "The model folder holds the model; the repository's .radical/ holds how the repository meets it. A measure line names a sensor; a sensor of .radical/sensors/sensors.json names a command, or a built-in adapter and its arguments ({ \"adapter\": \"playwright\", \"args\": [...] }). A measure line with arguments still runs, and radical check warns about it (measure-with-arguments). The repository's test file globs and CI artifact names are in .radical/radical.json (\"tests\": { \"include\", \"exclude\" }, \"ci\": { \"artifacts\" }); check.json keeps the model's rules and goals, its old settings are still read, with a warning (repository-settings-in-model), and the Inspector's Settings write them to radical.json. Reviews are recorded in .radical/reviews.json, in git; the model folder's is still read, and radical setup moves it. radical check warns about a description that names a path the repository does not have (description-path-missing)."
status: "accepted"

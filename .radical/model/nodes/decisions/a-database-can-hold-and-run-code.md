label: "A database can hold and run code"
alternatives: "A routine type of its own (procedure, function, package, trigger): an element per routine, 774 for one PL/SQL library, and a type C4 does not have. A component type allowed only in databases: a second name for what C4 calls a component. Keep the database passive and draw only the calls to it: the logic and what it calls stay out of the model, as before. Let a database deliver to a person: Oracle's UTL_MAIL sends through a mail server, the element that delivers."
consequences: "Models of systems built around their database show where the logic is and what it calls. A database with components is drawn as a frame around them, as a container and a web app are, and the Components viewpoint shows them; Components of a container stays a view per container and web app, since a view per database, most of them holding no code, would be noise. Existing models stay valid, since only allowed pairs and parents are added; a model on an edited copy of a preset keeps its own rules until it is reset. A team that wants the stricter rule narrows its metamodel, which asks before it refuses what the model holds."
context: "C4 makes a database a container, a runtime boundary around code that runs or data that is stored, and sets no rule on which elements a relation may join. The built-in metamodels treated a database as a passive store: no component inside one, no relation from it, no person using it, and in Radical it could not realise an entity, implement a state machine or perform a step. Assay's runs on Oracle and PostgreSQL code (an agent's run on Schemaverse and the Alexandria PL/SQL library, the held-out utPLSQL and Logger) found systems whose logic lives in the database: 56 PL/SQL packages calling S3, Slack and PayPal, a game whose rules are PL/pgSQL functions that set its lifecycle flags. Their models had to list the routines in the database's description and leave out what they call, the entities they keep and the lifecycles they move."
date: "2026-11-09"
decision: "A database is a container that may run code. In both built-in metamodels a component may be inside a database (an Oracle package, a library of routines), Interacts may go from a database to a system, container, web app, database, queue or component, and from a person to a database. In Radical a database may realise an entity, implement a state machine and perform a step. A database still delivers nothing to a person: a mail server or a service does. Assay makes a stored package a component of its database's element, its members named in its description, relates the code calling a member to that component, and lets the element holding the routines realise the entities whose tables only they use. Stored routines get no type of their own."
status: "accepted"

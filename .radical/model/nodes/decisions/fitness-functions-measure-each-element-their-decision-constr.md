label: "Fitness functions measure each element their decision constrains"
alternatives: "A property on each element with the path the sensor needs ({element.openapi}): puts the mapping onto the real system into the model. A fitness function copied into each service: the standard drifts per copy. Measuring a central standard in the central repository: it has none of the code. Context as environment variables or on stdin: chosen first, then replaced by one --context parameter, simpler to read in any language."
consequences: "A standard is checked in every repository whose elements it constrains, by that repository's own means, and one fitness function serves a TypeScript and a Java service alike. The model holds no paths, commands or repository links. A repository without the sensor a measure line names measures nothing there, and says so. A fitness function measured per element fails on one element: the finding names it. Built-in sensors keep running once per measure line, as before."
context: "A decision constrains elements: an ADR of the organisation's standards (REST and OpenAPI) constrains the containers of every system that follows it, and the fitness function that implements it says what to check. But a measure line ran once, with no element, in the repository of the fitness function's model: a standard of a central model was checked nowhere, and one decision constraining three containers was one measurement. Where an element's code lies, and how to check it, is the knowledge of the team that builds it, not of the model."
date: "2026-11-02"
decision: "A fitness function applies to each element its ADR constrains directly (FF implements ADR, ADR constrains element), whether the fitness function and the ADR are the model's own or fetched from another model of its federation: a constraint on an element makes the fitness function that element's, measured where the element is built. A measure line names a sensor; besides the sensors built into the CLI, the repository's .radical/sensors.json, at its top and outside the model, maps a sensor's name to the command that runs it there. radical sense run runs such a sensor once per element the decision constrains, passing --context with the whole context as JSON (the fitness function, the ADR, the element with its type, technology, parent and properties, and where the sensor may write measurements of its own); its exit code and duration are measurements, labelled with the element. radical check and the Inspector evaluate the fitness function's conditions for each element, in the repository that owns the element, as evidence of that element; it passes when it holds for every element. Amends Sensors measure, the model decides."

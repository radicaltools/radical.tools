label: "Agents check requirements against the person's words"
alternatives: "A reviewer with a language model in CI (independent, but needs an API key and costs at every pull request). A person reviewing in Studio's Inspector (most reliable, but only when someone looks). A deterministic rule in radical check (cannot judge meaning)."
consequences: "A requirement can be checked against what was said: by the agent when it writes it (the MCP server's answer) and again before the code, by radical check in CI from the person's words to the files of the tests, and by a person in Studio. What the rules compare is presence and form, not meaning (a negation inside a sentence, which of two values a word belongs to): the check of meaning is the agent's own reading, so some errors still pass; quotes make it cheaper and catch what was never turned into a requirement."
context: "An agent turns what a person says into EARS requirements and ADRs and then builds from those. In the benchmark, details the client stated (a value of 0, an e-mail address kept on the order) were changed on the way into requirements and decisions, and the code followed the changed text. The needs could not show it: they held the first request, and the answers to the agent's questions only in its own summary or nowhere."
date: "2026-11-12"
decision: "A need keeps the person's words: each question the agent asks about it and the person's answer go into its description word for word, not summarised (\"Q: …\" on one line, \"A: …\" on the next). A requirement's derives relation to a need carries the words of the need it rests on (property quote, one verbatim fragment of at least two words per line). Before it writes code, the agent calls review_requirements: it lists each requirement added or changed on the branch, and each one a changed need leads to, with its sentence next to the quoted words (the whole need where nothing is quoted) and the values that differ, and asks the agent to write down every value the requirement states with the words that say it and to correct a requirement whose words say something else. radical check reads the words without a language model: as whole words, Markdown and typography aside, and values in their forms (20 percent as 20%, 15 minutes as 900 seconds, 12.30 € as 1230 cents). It reports a derives relation to a need without a quote (warning, when turned on; a goal in percent), a quote the need does not hold or on a relation to anything but a need (error), an answer of a person in a need that no requirement quotes (warning), a hard value a quote says that its requirement does not, or gives another sense (the side of a limit, the unit, the order, the rounding), and one the requirement says that no quote or its rationale says (warnings), a quoted value no scenario of the requirement names, an example of the person no scenario holds whole, and, with the repository's tests, a value of a scenario the files of its bound tests do not use (warnings). The MCP server names what a write brings in of these at once."
status: "accepted"

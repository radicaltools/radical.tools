label: "New model starts with the metamodel's views"
alternatives: "Views made when filled, as in a Forge run (a blank model would then start with no views, which is what the owner wanted changed). A separate Views step after Create (one more screen; the owner chose the choice under Metamodel). A checkbox instead of two options (the owner chose two options with Customise…). Empty as the default (the owner chose the metamodel's views)."
consequences: "A model starts in the structure the user goes on to work in, and a Forge run on it reuses those views. A view shows nothing until its chain gives an element, and a group holds no view until an element of its types is added, so a new model shows many empty views at first; Empty keeps the old start. The views follow the metamodel only through its viewpoints: a metamodel without viewpoints offers Empty only."
context: "A new model started with no views: the user built its structure view by view, though the metamodel already names the views it is meant to be read through (its viewpoints) and radical.tools' own model shows how to fold them into folders. Radical Forge offers that structure before a run (ADR Forge asks for the view structure), but a model started by hand got nothing. The owner asked New model to offer the structure of groups and views, tied to the metamodel picked: first the metamodel, then the question about its views."
date: "2026-10-23"
decision: "The New model step asks, under Metamodel, for its Views: Views of the metamodel (the default) or Empty. Views of the metamodel start with a Structure view of all elements, named All elements, at the top of the list right under the All elements table, so that the whole model can be drawn and laid out as well as listed; then the Radical structure of a Forge run (radicalViewpoints: a view of each viewpoint in the folders Conceptual, Logical and Governance, another metamodel's in a folder named after its group; the whole-model viewpoints a view per element stands in for left out), with Customise… to tick them one by one, the list following the metamodel picked. @radical/common's metamodelViews makes them, in the order of the list: a view of each chosen viewpoint, and for a viewpoint that draws one element (ViewpointDef.subject) a group of views per element, which gets a view of each element as it is added (syncViewGroups). Unlike a Forge run's, they are made at once, before the first element. A model with no elements opens on All elements, whatever views it has."
status: "accepted"

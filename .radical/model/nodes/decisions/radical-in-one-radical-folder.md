label: "Radical in one .radical folder"
alternatives: ".radicaltools/: the brand and the npm scope, but radical is the command, the file extension and the state folder already. The model visible at the root (architecture/) and .radical/ only for configuration and state: two places again. One shared .radical/state/ beside the model: Studio in a browser, opened on the model folder, cannot reach it. Keeping the model's state in its .radical/: .radical/model/.radical/ reads like a mistake. The model in .radical/architecture/: a Radical model holds more than architecture (requirements, a domain model, processes), so the folder is named model. Crucible's plan beside sensors.json in .radical/: everything of Crucible is in one folder, .radical/crucible/. The sensors' scripts in tools/ beside the repository's other scripts: they serve only radical sense run, so they go with the sensors."
consequences: "One folder to know, to ignore in a search or to copy; tools find the model with no --folder. The model is in a hidden folder: ls and rg leave it out unless asked, so an agent reaches it through the MCP server, as it should. A state file is written only to .state/, and read from .radical/ too while .state/ lacks it, so a version before this one and one after it do not see each other's selection, agent turns or write lock: run one version on a folder. A repository moves once, in one commit of renames."
context: "A repository that uses Radical had its files in several places: the model folder (architecture/ or another name) with its state out of git in the model folder's .radical/, radical.sensors.json and crucible.json at the repository's root, crucible/findings/ kept and .crucible/rounds/ ignored there too. Each tool found its file another way: a model folder named on the command line (the working directory by default), a search up to the repository's root, paths in crucible.json. The repository's root filled up with files only Radical reads, and model files saved at a root by mistake made the root look like a model."
date: "2026-11-02"
decision: "Everything Radical keeps in a repository is in one folder, .radical/, at its root: the model in .radical/model/, the repository's sensors in .radical/sensors/sensors.json, with the scripts only its sensors run beside it (their commands run from the repository's root), Crucible's plan in .radical/crucible/crucible.json, its findings in .radical/crucible/findings/ (in git) and its rounds in .radical/crucible/rounds/ (out of git). A model's state out of git (base, cache, fetched models, test results, measurements, selection, agent turns, Forge run) is in the model folder's .state/, not .radical/: a model folder opened on its own, as Studio in a browser opens one and sees nothing beside it, keeps its state. The CLI, the MCP server and Crucible, given no model folder, use .radical/model of the repository they run in, found from the working directory up. The old layout is still read: a model folder named, or a working directory that is one, or architecture/ at the root; radical.sensors.json and crucible.json at the root; a state file the folder's .radical/ has while .state/ lacks it. radical setup sets up a new repository in .radical/ and offers to move an old one with git mv, pointing .mcp.json and the hooks at the new folder; setup --status warns about the old layout. Only what other tools need at the root stays there: .mcp.json, .github/, the launcher, reports/."

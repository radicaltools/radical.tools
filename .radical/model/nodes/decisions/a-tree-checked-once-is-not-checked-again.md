label: "A tree checked once is not checked again"
alternatives: "Keep checking twice: the second verdict is the first one's, later. A mark in the Actions cache: a run on main cannot read the cache of a pull request. A mark in a bucket, as IsoStride keeps it: a bucket and a role for the pull-request runs, for what an artifact does. Believe the pull request a commit was merged from: a squash merged after main moved on is another tree than the one checked. Deploy the build the pull request's run made: it is stamped with another commit, and a deploy builds what it uploads once."
consequences: "A deploy of a merged pull request that was checked takes the build and the upload only. The mark is by tree, so what main holds is exactly what was checked: a merge after main moved on gives another tree, which is checked whole. A mark is trusted as the run that kept it: a pull request that changes ci.yml could mark its tree without checking it, as it could turn its own checks green before; the review of workflow changes is the guard, and the run of a fork is not believed. The marks are GitHub's artifacts, so no bucket and no key is added; a mark gone after a week costs one whole check. The deploy job's checking steps are left out one by one, so the job that deploys still builds what it uploads (Deploys take the build's digest)."
context: "ci.yml runs on a pull request, on its merge commit: the tree as it would land. deploy.yml then ran the E2E suite, the workspace boundary check, the type-check and the unit tests again on main before it built, in most merges on that very tree: a quarter of an hour before each deploy for a verdict already given. IsoStride's pipeline keeps a mark of each tree its check passed and leaves the check out on master for a tree with a mark; the product owner asked for the same here (2026-11-26)."
date: "2026-11-26"
decision: "A run of ci.yml whose gate job passes marks the tree it checked: an artifact named checked-<the tree's git hash>, kept for a week (tools/ci/checked.mjs mark, in the gate job after the gate). It marks nothing when the E2E suite was skipped by the skip-e2e label, or when the suite wrote new screenshot baselines, which that run compared loosely. deploy.yml on main first asks whether its tree has a mark (tools/ci/checked.mjs known, job known): an artifact of that name that has not expired, kept by a completed, successful run of ci.yml of this repository itself, not of a fork. With one it leaves out the E2E suite, the boundary check, the type-check and the unit tests, and builds and deploys; without one (a push straight to main, a merge after main moved on, a mark expired, the question unanswered) it checks the tree whole, as before."
status: "accepted"

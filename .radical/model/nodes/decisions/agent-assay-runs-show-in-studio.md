decision: "After every assay_* call, the MCP server writes the run's status to .state/assay-run.json in the model folder (@radical/common formats/assayRunStatus.ts), as it writes an agent's Forge run (ADR Agent Forge runs show in Studio): the client's name, the repositories read (units and facts), the sources, each stage of C4, Explore, Documents, Domain, Processes, State machines and Scenarios (pending, working, done or skipped, with the plans applied and refused and the elements and relations added), the proposals (waiting, accepted, rejected) and active / finished / closed. The server infers the stage from the calls: assay_start starts C4, assay_explore starts Explore, and a plan is of the latest stage its contents name (requirements: Scenarios; state machines; processes; entities or domain elements: Domain; needs or decisions: Documents; mockups: Explore; else C4). A stage the run moves past with no plan is skipped; a later plan of an earlier stage counts there without moving the run back. assay_finish finishes the run, and the server shutting down closes an unfinished one. Studio polls the file every 2 s as it polls the Forge run's. An Assay button beside the Forge button appears only while there is a run: it pulses blue while the agent works and amber while proposals wait, shows the stage it is at, and opens a read-only view of the stages with one line of status, the repositories, the plans and proposals and Follow on the canvas, which stops once neither the Forge nor the Assay run goes on; the button goes away 30 minutes after the run ended or went quiet. Studio never writes to the run."

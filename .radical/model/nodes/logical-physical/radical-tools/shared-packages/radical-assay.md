packages/assay: Radical Assay's deterministic part, used by the CLI and the MCP server. repositories.ts takes the code given (a repository, a directory of repositories, a folder of code with none inside, a .zip file unpacked first); files.ts lists a repository's files (git ls-files in a repository, else a walk) and reads them once; stacks.ts finds the units of every stack (npm, Maven, Gradle, Go, .NET, Python, VB6, a lone Dockerfile) with their dependencies, references by path and test framework, and the groups of .sln and .vbg files; runtime.ts reads docker-compose files and Kubernetes manifests (services, their roles, environment addresses) and a unit's configuration (Spring names, ports, addresses), aspire.ts .NET Aspire AppHosts; code.ts reads a unit's sources and configuration: URL paths and addresses in strings, hosts given as defaults or named in variables, gRPC services registered and clients made, connection strings and the tables SQL names; domain.ts reads the tables SQL files create and alter and ORM classes map (JPA, Entity Framework Core, Django, SQLAlchemy, TypeORM, Prisma) with their columns and foreign keys, and the values statuses take (enums named for one, CHECK … IN, SQL ENUM) with the lines that set each; entries.ts reads the entry points (HTTP routes in code, a VB6 form's caption, menu items and buttons with their Click handlers, scheduled jobs, message handlers); extract.ts puts them together with OpenAPI operations, the tests reports name and the repository's documents; sources.ts lists a repository's README, docs and ADR records, and takes sources of documents (folders, files, .zip files, public links fetched once without credentials, a sign-in refused) into the central repository's <central repository>/.radical/assay/sources/ as text (HTML as Markdown, a PDF's text), each a document fact with its title and headings; link.ts links units across repositories (references and dependencies, http, gRPC, addresses, depends_on, data with the service a database runs on); plan.ts checks a plan (cited facts exist and join a relation's ends, observed claims cite a fact that states them and no document, scenarios rest on passing tests, explored paths or quoted code, entities on table facts and joined only where a foreign key states it, every process step and state machine transition on what it rests on, a state on a status value or quoted code, an inferred claim, a need, a decision or a requirement no test checks may rest on code or documents the agent quotes) and cite.ts checks a quotation; skeleton.ts writes the pending tests of scenarios drawn from the code, for the unit's test framework; bench/ measures them on pinned public repositories.

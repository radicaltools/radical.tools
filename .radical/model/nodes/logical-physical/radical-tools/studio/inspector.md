The Inspector, a place of the activity rail as the Views section is (components/Inspector.tsx: InspectorSection, its tabs in the left panel through LeftPanel's place, each a card as the views are, and InspectorMain, the tab picked in place of the view, under a bar with the freshness chips and the verdict; components/inspector/: OverviewTab, ModelTab, ImplementationTab, MeasurementsTab, ThisChange, shared, fixes, TracePanel, Freshness, attention; Toolbar.tsx InspectorRailButton above Settings, coloured as the verdict with the count of errors; components/CheckSettingsDialog.tsx with inspector/SettingsTab and settingsDraft, opened from Settings → Inspector settings…; persistence/inspector.ts, navigation.ts useInspectorNav and showElement). Runs checkModel on the model as it is edited with the folder's check.json, .state/test-results.json and .state/measurements.json and shows it in the tabs Overview, Model, Implementation, Measurements and This branch, in Designer, Viewer and Presenter; open or closed is kept across perspectives and reloads, ⌘/Ctrl+J opens it and goes back to the view, and a section's tab on the rail goes back to the view (ActivityRail over). Every element it names is a link: showElement shows it in the perspective open, on the view pickViewFor picks as Quick Search does, selected with its properties card, the Inspector giving the view back. Its one-step fixes (Add scenario, Add fitness function) follow the perspective (useFixOffer): made at once in Designer, '… in Designer' in Viewer and Presenter (editAsDesigner), refused while a milestone is shown (liveModelEditRefused). This branch lists every element added, changed and removed since the base with its fields, and for the requirements and ADRs what the tests say, under the switch Show the changes on the canvas (Changes on branch, there only); without a base it gives the commands that save one. Measurements (components/inspector/MeasurementsTab.tsx) lists what the sensors measured, by metric, the metrics with a failing reader first: each measurement with its labels (an element label a link to the element), value, unit, source and age, under it the scenarios and fitness functions whose conditions read it (readersOf, from the evidence: a condition's result names the measurement it was decided by) with the condition, its outcome and Path to its verification path, a text filter over metric, labels, source and the readers' names, and after them, under Not measured, the metric conditions no measurement matches; its card counts the measurements and the readers that fail or find them stale. Inspector settings edit check.json (goals, severities, baselines, test-unbound files; Ratchet; the change marked when it loosens the gate, and its diff) and save with saveCheckConfig only what the draft changed over check.json and .radical/radical.json read again at Save (settingsBases, settingsOf), so an agent's change made meanwhile stays; an unsaved draft is marked in the Settings menu. The button is enabled by a check report, measurements or a base (inspectorAvailable). Puts the check's evidence and findings by element into @radical/ui's useCardVerification for the card's Verification section in every perspective. Passes checkModel the Hub's concern packs from the catalogue the Hub store loads (fetched once a folder model is checked) and shows each unaddressed concern with its elements, its questions and Answer the questions…, which opens the Hub import dialog on the pack bound to the first element (openConcern, the radical:open-hub event the toolbar listens to). Path, in the card's Verification of a need, requirement, scenario, ADR or fitness function, opens the Inspector on the verification path (components/inspector/TracePanel.tsx: traceOf drawn in columns on a CSS grid, the lines between the cards in SVG from their measured places, a test's failure message and its link to VS Code where the repository's folder is known, Only what does not pass, Back over the paths opened from it, Show on each card); the element on it is part of the route (useInspectorNav.trace, the tr segment), and persistence/verificationPath.ts offers it to the card. It checks the live model, also while a milestone is shown; Path is disabled, saying why, for an element only the milestone shown holds.

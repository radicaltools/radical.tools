After the first ten packs (2026-10-22, translated from Polish): I need better quality concepts, and I do not like the lack of classification; in my view: communication, data, API, authentication, tech stack, resiliency, maintainability, security, quality.

What lowers the quality: too few questions and variants, no sources, fitness functions that cannot be run, contents too general, an inconsistent classification. The list of groups is to be thought through.

Agreed 2026-10-22: one axis, the area of the architecture where the decision is made, in eight groups (Identity & access, Security, Data, Integration, Reliability, Operations, Maintainability, Technology), mapped to the ISO/IEC 25010 quality characteristics; and a minimum standard for every pack: 3-5 questions with options that say when to pick them, measurable requirements, decisions that name technologies and criteria, fitness functions with a named tool and a snippet to copy, and sources; the catalogue refuses a pack below it.

Later the same day: there is a problem when I import several concepts into Studio at once, only one wizard starts. Also, I would like a dedicated view to be made in the model for the concept. Split the runtime stack into backend, frontend and infrastructure. Add something where I can decide 1. the architectural style, e.g. hexagonal, 2. microservices, 3. monolith and so on, and I want the communication style covered: request/response, message-based, async. (Agreed: a new group, Architecture.) Remove the sources from the Hub: good that you use them, but I do not want them listed. Remove Copy JSON and Download too.

"What is missing is a check that the requirement agrees with the need it was written from." Found in the Radical benchmark: the agent asked the client and was told that a product never received at a cost shows no average and its stock is worth 0, and that an order on an account carries the account's e-mail address; its requirement said the stock value is null, and its ADR that the order's e-mail is null, and the code followed them. The needs held only the request that started each step: the answers were summarised, or not written down at all. Asked: the agent checks itself, through the MCP server, before it writes the code. Then: "What if the need were linked to the requirement by a relation that says which part of the need the requirement realises; fetching the relation with its nodes would make the assessment easier." Asked one by one: a quote that is not in the need is an error; check also names each answer of a person in a need that no requirement quotes. Then: "I also want to extend the deterministic check, e.g. checking the words in the relation." Chosen: both value rules, a value the quote says and the requirement does not, and a value the requirement says that no quote says unless its rationale names it. Then: "Review the solution and suggest further fixes: I want to check as much as possible deterministically, without a language model." A review found holes in how the words were read (a quote of "at most 10" matched inside "at most 100", a quote of a single character, Markdown and answers on their question's line misread, a quote on a relation to another requirement counted as the person's words, values in other forms such as "20 percent" or "15 minutes" reported as different) and the value rules slow on large models (48 s for 5,000 requirements). Measured on the benchmark: 36 of 94 scenarios with values named one their bound test did not use, 16 of them one the whole test file did not hold; of the client's 13 worked examples, 5 reached one scenario whole. Chosen: fix the holes first, then a scenario's values in its tests' files, the person's examples in a scenario, the findings in the MCP server's answer to a write, and the sense of a value (the side of a limit, the unit, the order of a list, the rounding).

"What is missing is a check that the requirement agrees with the need it was written from." Found in the Radical benchmark: the agent asked the client and was told that a product never received at a cost shows no average and its stock is worth 0, and that an order on an account carries the account's e-mail address; its requirement said the stock value is null, and its ADR that the order's e-mail is null, and the code followed them. The needs held only the request that started each step: the answers were summarised, or not written down at all. Asked: the agent checks itself, through the MCP server, before it writes the code. Then: "What if the need were linked to the requirement by a relation that says which part of the need the requirement realises; fetching the relation with its nodes would make the assessment easier." Asked one by one: a quote that is not in the need is an error; check also names each answer of a person in a need that no requirement quotes. Then: "I also want to extend the deterministic check, e.g. checking the words in the relation." Chosen: both value rules, a value the quote says and the requirement does not, and a value the requirement says that no quote says unless its rationale names it.
Translated from Polish.

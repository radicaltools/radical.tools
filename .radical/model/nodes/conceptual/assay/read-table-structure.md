action: "the system shall record the table as a table fact of that unit with its columns and, for each foreign key, the column and the table it references, each with its file and line; migrations count in their order, a down migration (golang-migrate's and dbmate's .down.sql, Flyway's U__ undo) not at all, so a table a later one drops (DROP TABLE, Schema::drop) is gone and one it renames has its new name; Rails' db/schema.rb gives a Rails application's tables, columns and foreign keys (add_foreign_key); Ecto's migrations (priv/<repo>/migrations) are replayed in their order, their down functions and the second statement of execute up, down aside, with the SQL they execute or load by name from the one file of that name the repository holds (execute unwrap(\"create-events-v2\")) and the tables Oban's migrations create, over a structure.sql dump beside them; SQL in a framework's migration files (db/migrate, priv/…/migrations, database/migrations) names the tables of its time, not the unit's; a table in a schema is named by its name, or by schema and name where two schemas of the unit hold one name, and a schema is no table; an SQL file in no unit's folder is the schema of every unit whose code names one of its tables or that uses the database it names (USE, CREATE DATABASE), by its code or by a service running it; an Access file's tables, columns and relationships are those of the units using it (read by the MCP server; the CLI reads no Access file and notes it); a Django model is a class of an app's models deriving from models.Model, from another model of the repository or from a model base of Django or Wagtail (Page, Orderable, ClusterableModel, AbstractFormField, BaseSiteSetting…) and not abstract, and a many-to-many field adds its join table; a Room entity is the table its @Entity tableName names, else its class, with the foreign keys its ForeignKey entries state; SQL in a string of Java or C# code that creates tables (Dapper's CREATE TABLE, joined with + over lines) declares them, each on its line; an Entity Framework Core class is an entity only of a unit its DbContext's project is or references (a clean architecture's Core), not of another unit with a class of its name; an Entity Framework Core class's [Table] attribute (with its Schema) names its table over its DbSet's name, whatever attributes stand beside it; a Doctrine entity (#[ORM\\Entity]) is the table its #[ORM\\Table] names, else its class in snake case, with the join tables its many-to-many associations name; a view (CREATE VIEW) and a database's own tables (sys…, information_schema, pg_catalog, ClickHouse's system) are no tables"
ears_type: "event-driven"
rationale: "Entities are the tables a system keeps; their foreign keys are the only evidence of how they belong together."
trigger: "a unit's SQL creates or alters a table, its Laravel migrations create one, its code declares an ORM entity (JPA, Entity Framework Core, Django, SQLAlchemy, Doctrine, TypeORM, Prisma), or the repository holds the Access file (.mdb, .accdb) a unit uses"

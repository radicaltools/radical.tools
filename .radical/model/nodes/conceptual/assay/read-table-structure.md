label: "Read table structure"
action: "the system shall record the table as a table fact of that unit with its columns and, for each foreign key, the column and the table it references, each with its file and line; migrations count in their order, so a table a later one drops (DROP TABLE, Schema::drop) is gone and one it renames has its new name; a table in a schema is named by its name, or by schema and name where two schemas of the unit hold one name, and a schema is no table; an SQL file in no unit's folder is the schema of every unit whose code names one of its tables or that uses the database it names (USE, CREATE DATABASE); an Access file's tables, columns and relationships are those of the units using it (read by the MCP server; the CLI reads no Access file and notes it); a Django model is a class of an app's models deriving from models.Model, from another model of the repository or from a model base of Django or Wagtail (Page, Orderable, ClusterableModel, AbstractFormField, BaseSiteSetting…) and not abstract, and a many-to-many field adds its join table; a Doctrine entity (#[ORM\\Entity]) is the table its #[ORM\\Table] names, else its class in snake case, with the join tables its many-to-many associations name; a view (CREATE VIEW) and a database's own tables (sys…, information_schema) are no tables"
ears_type: "event-driven"
rationale: "Entities are the tables a system keeps; their foreign keys are the only evidence of how they belong together."
trigger: "a unit's SQL creates or alters a table, its Laravel migrations create one, its code declares an ORM entity (JPA, Entity Framework Core, Django, SQLAlchemy, Doctrine, TypeORM, Prisma), or the repository holds the Access file (.mdb, .accdb) a unit uses"

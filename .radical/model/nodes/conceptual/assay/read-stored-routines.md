type: "requirement"
label: "Read stored routines"
action: "the system shall record each routine as a routine fact with its name (an Oracle package's member as package.member), its kind (procedure, function, package, trigger) and dialect (Oracle's PL/SQL, SQL Server's T-SQL, PostgreSQL's PL/pgSQL, MySQL), the table a trigger is on and the function a PostgreSQL trigger runs, and the tables its body reads and writes and the routines it calls among those the repository knows, each with its file and line; a package's members are the procedures and functions at its top level, not the subprograms declared inside a member; comments and strings are read past in one pass (a string may hold --, run over several lines, or be Oracle's q'[…]'); the routines are those of the database's final state: one a script drops and creates no more after is gone (an installer's helpers dropped at its end), while a teardown script (named for dropping, uninstalling or cleaning up, or one that drops and creates nothing and is no versioned migration) and Sqitch's revert/ and verify/ scripts drop nothing; a routine in a unit's folder, or in a script of the one unit using it, is that unit's, and one in no unit's folder the database's own; a routine's body is its statement (a PostgreSQL body from AS $$ to its close, else to Oracle's / line or SQL Server's GO), so what follows it (REVOKE ON PROCEDURE x()) is no call of it, and Oracle's $$NO_OP flag opens no body; a Sqitch project's deploy scripts are read in its plan's order, its reworked (name@v1.0.sql), revert/ and verify/ scripts not; a script that runs others (SQL*Plus @@) is no teardown, nor is a teardown script one of them runs (a runner's drops at its end count), and a teardown script is named for it at its start or its end (drop_x.sql, hr_drop.sql), not in a migration's or a Sqitch change's name (player-drop_password.sql); a repository's developer tooling (development/, dev-tools/, tooling/) holds none of its routines; a coverage folder git tracks holds code (utPLSQL's ut_coverage), not a report; a Sqitch change the plan reworks runs, where the plan first has it, the script as the tag after it froze it (trigger-destroy_ship@v1.0.sql), and its own script where it last appears, so a trigger only the earlier version creates stays; a procedure, function or trigger created again is its last script's (a package and its members their spec's and body's together); a PostgreSQL body in a named dollar quote ($get_player_id$) is PostgreSQL's"
ears_type: "event-driven"
rationale: "Much of the logic of systems on Oracle, SQL Server or PostgreSQL lives in the database: a model without its routines misses what the code calls and what changes the tables."
trigger: "a repository holds a database's scripts creating procedures, functions, Oracle packages or triggers (.sql, and Oracle's .pks, .pkb, .prc, .fnc, .trg and the like)"

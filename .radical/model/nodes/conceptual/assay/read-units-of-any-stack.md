its JUnit the one its tests import, JUnit 4 before Spring Boot 2.2; a Gradle project's dependencies on others in any configuration, by project(':a:b') or by type-safe accessor projects.a.b, and those the convention plugins it applies add in their code), Go modules with their main packages, .NET projects (with the project references Directory.Build.props and Directory.Build.targets add by their conditions on the project's name and path) and SQL Server database projects (.sqlproj), a build project git tracks in a build folder (build/_build.csproj), Python projects, Ruby projects (a Gemfile or gemspec; an app when it is a Rails application, known by its module, or has a config.ru), Elixir projects (mix.exs; an app with its own application module or on Phoenix; an umbrella's root holds its apps and is no unit), Rust crates (a Cargo.toml with a [package]; an app when it builds a binary), each with its dependencies by path, VB6 projects and groups (each reference read once, by its library's name, DirectX among its technologies, its description from its version information; a reference no code of the unit uses is marked unused and names no technology; several projects in one folder are one unit, known by each project's name and binary), and a folder with a Dockerfile no other unit claims, unless it is a development container (.devcontainer) or copies other units' projects or folders, which it builds (the only unit below it that it packages is then known by the Dockerfile's folder), and a Dockerfile alone in its folder builds what other folders hold unless it copies nothing of the repository (a stock image with an agent added, a server it fetches and builds); a compose service built from a context holding several units runs the one its Dockerfile builds or publishes; a package.json of tooling alone (devDependencies, no script that runs an application) beside a Python project with its entry point leaves the folder to Python; a workspace root whose manifest only declares the workspace (a pyproject.toml without [project], a package.json of workspaces and scripts, a go.mod with no Go code of its own, a tools.go pinning tools (//go:build tools) aside) is no unit, nor a package.json of lint and format tools alone (markdownlint, Prettier, Biome, ESLint), nor a library vendored into a web application (wwwroot/lib), nor a Dockerfile that only adds scripts to a stock image while the compose service built from it mounts a unit's folder as its volume (that service runs the unit it mounts); a Go module required through a replace directive is a dependency on the unit in that folder; each an app or a library, with the stack it is written in, and with the units it depends on resolved by name or by path"

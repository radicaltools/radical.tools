## Steps

1. Sample with a milestone 'v5 – Lifecycles' saved before the transition Held -> Booked existed (seeded into the saved document)
2. Open v5, Event catalogue, double-click 'Case approved', Delete element
3. Propagate to later milestones; back to Current (live)
4. Metamodel editor, Validation

## What differs

```text
Expected: The live transition Held -> Booked loses its event, as a delete made on the live model does (forgetNodesInReferences); Validation stays at 0
Actual: Event gone from the live model, a transition v5 also holds lost its event, but Held -> Booked keeps event 4e611ecf-...; Validation 0 -> 1: 'points at nothing valid (no node has id ...)'
Seen: 2 of 2
Where it probably comes from: guess: packages/ui/src/store/diagramStore.ts commitMilestoneChanges -> applyDiff removes nodes, relations and sequence steps but never calls model.forgetNodesInReferences on later milestones and liveBackup
A test that would catch it: packages/ui/tests (milestone propagate): a later model holding a transition whose event the edited milestone deletes; after commitMilestoneChanges('propagate') the live and later relations have no event pointing at it, validateModel reports nothing
```

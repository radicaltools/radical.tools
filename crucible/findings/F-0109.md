## Steps

1. Sample, a table view: F2 on a row, type a new name
2. Press F5, then Esc
3. Processes (Warnier): edit a step's name, type, press F5, Esc
4. For comparison: the properties card's name field, type, F5

## What differs

```text
Expected: The typed name is saved, then the presentation starts, as from the properties card
Actual: Table: the presentation starts and the row keeps its old name; Warnier step: 'Enter the payment' stays; the card saves 'Card Networks XYZ'
Seen: 2 of 2 (re-run by the coordinator after the decision)
Where it probably comes from: the table's F2 rename and WarnierView's step name editor do not commit on blur/unmount when F5 starts the presentation (the card commits on blur)
A test that would catch it: apps/e2e/tests/studio: F2 in a table and a Warnier step name, type, F5, Esc: the new name is saved
```

## Fixed (2026-10-26)

F5 blurs the focused field before presenting, so a name typed in the table, a Warnier step or a slide is saved, then the presentation starts.

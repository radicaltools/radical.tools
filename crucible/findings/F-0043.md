## Steps

1. Seed needs 'Pay by card' and 'Audit' and a wiki with the chain: needs whose name has 'Pay' → requirements
2. Open its Overview: no writing line at the top; click Add element
3. Same with the built-in Responsibilities chain as a wiki on an empty model
4. Open the same 'Pay' chain as a table

## What differs

```text
Expected: As the table: Need offered (the table shows '+ Need · the filter won't show it'), a line to write a need (one named 'Payment refunds' passes the filter), or at least a true reason
Actual: Both wikis: 0 writing lines at the top, Add element menu empty with the hint 'No root types in metamodel'; before #252 the wiki offered these types
Seen: 2 of 2
Where it probably comes from: packages/ui/src/components/WikiView.tsx: topChoices keeps only !c.hidden choices; meetFilters marks a text or relation-has filter hidden for any new element, so topTypeOptions is empty and WikiOverview shows emptyHint 'No root types in metamodel' (a guess)
A test that would catch it: apps/e2e/tests/studio/wiki.spec.ts: a wiki whose first level filters needs by the text 'Pay' offers Need in Add element (or a message naming the filter, not the metamodel) and a 'Write a need' line; writing 'Payment refunds' shows it
```

## Fixed (2026-10-23)

A wiki whose first level filters by name or relation offers its types at the top, marked "the filter won't show it", as the table does; it never says "No root types in metamodel" when the chain has types.

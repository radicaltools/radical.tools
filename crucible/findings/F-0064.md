## Steps

1. Sample, Designer, Payment lifecycle
2. Milestones: + New milestone 'M'
3. Select the Payment lifecycle state machine, Delete, Remove from model
4. Open milestone M, Views tab

## What differs

```text
Expected: M holds the state machine, so the State machines group lists Payment lifecycle and Fraud case lifecycle, and Payment lifecycle draws its 9 elements
Actual: M holds the state machine (8 of its elements saved, M.views is {}), but the group shows '1 view', only Fraud case lifecycle; a deep link to view-payment-lifecycle in M lands on All elements with 0 drawn
Seen: 3 of 3
Where it probably comes from: guess: packages/common/src/model.ts planViewGroups/syncViewGroups removes the subject's view outright; the F-0053 fix keeps only view lists in DiagramSnapshot.views, so the milestone has no view to show
A test that would catch it: packages/ui/tests/milestoneDeletedSince.test.ts: delete a group's subject on the current model, select a milestone holding it: the group lists that subject's view and it draws the subject's children
```

## Fixed (2026-10-26)

A milestone keeps the view per element of an element the live model deleted, with its places, and shows it in its group (keepViewsInMilestones, milestoneOnlyView), in Studio and over MCP.

## Steps

1. Sample, Designer, Core Banking: select Fraud Detection, Delete, Remove from model
2. Drag a Software System from the palette onto Core Banking
3. Milestones: v3; double-click Transactions DB, Actions › Hide from view, Propagate
4. Milestones: Current (live)

## What differs

```text
Expected: Current Core Banking draws the new System and not Transactions DB; its list does not name the deleted Fraud Detection; folds made on the live model stay
Actual: The new System is not drawn (still in the model, the card says 12 nodes); the saved view-core.nodeIds lacks it and contains ctn-fraud, which the live model deleted. The same with folds: folding Risk & Data in v3 and propagating unfolds Access & Security, folded on the live model
Seen: 3 of 3
Where it probably comes from: commitMilestoneChanges: for a view the milestone keeps its own way, each key that differs between its copy and the shown view (nodeIds, collapsedNodeIds…) is written whole into keptLiveViews, so the live view gets the milestone's old list instead of the edit
A test that would catch it: packages/ui/tests/milestoneDeletedSince.test.ts: live delete X (milestone M holds it), live addNode Y on view V; selectMilestone(M), removeNodeFromView(V, Z), commitMilestoneChanges('propagate'): V lists Y, not X, not Z
```

## Fixed (2026-10-26)

Propagate carries only what the milestone's edit changed (viewEdited), so the live view keeps elements and folds added since and no longer lists elements the live model deleted.

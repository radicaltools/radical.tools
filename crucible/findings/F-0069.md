## Steps

1. Bookstore moved to a folder
2. Right-click Customer → Discuss, type a comment, click Post comment
3. Press Escape

## What differs

```text
Expected: Focus stays in the panel (e.g. the comment field); Escape closes the panel, as it does before a post (its close button says 'Close (Esc)')
Actual: After the post document.activeElement is <body>; Escape leaves the panel open (1 dialog). Same after Resolve thread
Seen: 2 of 2
Where it probably comes from: DiscussionPanel.tsx: the clicked button becomes disabled (empty draft / pending) and nothing moves the focus; the Escape handler sits on the aside only
A test that would catch it: apps/e2e/tests/studio/web-discussions.spec.ts: post a comment, expect focus inside the dialog, press Escape, expect the dialog to be gone
```

## Fixed (2026-10-26)

The panel holds the focus while a post or resolve saves, then gives it back to the button or the comment field; Start a new thread instead moves it to the comment field.

## Steps

1. Sample as a folder; Milestones: v3 – Full Platform, Core Banking
2. Select Transactions DB, Delete key, Hide from current view, Continue editing (chip: unsaved)
3. Agent: update_node ctn-mobile label 'Mobile App X' (on no view shown)
4. Wait 6 s; Propagate; Current (live)

## What differs

```text
Expected: Transactions DB stays hidden in v3 while the edit is unsaved; Propagate takes it off the current Core Banking (as it does without the agent's write: run with 'control')
Actual: 6 s after the agent's write Transactions DB is drawn again in v3 (0 -> 1), chip still '· unsaved'; after Propagate the live Core Banking draws it and views.json lists ctn-db-tx; control without the agent: stays hidden, Propagate removes it from the live view
Seen: 2 of 2
Where it probably comes from: guess: diagramStore loadDiagram (outsideChange with a milestone shown): ShownMilestone keeps the milestone's nodes, relations and sequences, then showMilestoneViews(state, snapshot from disk) shows the views as saved, dropping the view edits made in the milestone
A test that would catch it: packages/ui/tests/milestoneViewEdits.test.ts: selectMilestone(v3), hide an element from a view, loadDiagram(same document with an unrelated change, {outsideChange: true}): the view in the milestone still hides it and commitMilestoneChanges('propagate') removes it from the live view
```

## Fixed (2026-10-26)

An outside change re-applies the milestone's unsaved view edits, so a hidden element stays hidden and Propagate takes it off the live view.

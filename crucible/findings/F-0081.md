## Steps

1. Seed a generated pile of 300 elements (systems with containers and databases, people, ADRs) whose view has a row alignment of adr0, sys3, person6, adr10, sys15
2. Open the view in Designer and run Smart Layout four times
3. Compare with the same pile without the row

## What differs

```text
Expected: As without the row: after the first run, 'nothing left to tidy' and nothing moves
Actual: Without the row: runs 2–4 'nothing left to tidy', 0 moved. With the row: run 2 136 moves (300 of 300 moved, 186 by one shift of 501,0), run 3 33 moves (300 moved), run 4 36 moves (299 moved); the same on a 60-element pile (15, 17, 10 moves)
Seen: 3 of 3
Where it probably comes from: packages/layout/src/tidy/index.ts runTidyLayout: enforceAlignments runs after the best-state guard and the top-left normalisation, so the layout handed over is not the one Tidy judged; the next run starts from the aligned one and the normalisation shifts the rest (guess)
A test that would catch it: packages/layout/tests/tidy/craft.test.ts: a pile with an align constraint tidied twice (the second from the first's positions): the second is keptCurrent with 0 steps
```

## Fixed (2026-10-26)

Alignments are lined up at the start, kept by every move and enforced before the move to the top left, so with a row the second and later runs say nothing left to tidy.

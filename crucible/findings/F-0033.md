## Steps

1. Bookstore + a wiki view: API's page, Edit API → Add or link… → uses……: Bookstore is listed; picking it is refused
2. A table System ← container (uses): + under Bookstore lists API under Existing; picking it is refused, then 'API was linked, but this view's filter does not show it.'
3. New model: drop an ADR onto a Software System; wizard → Affected elements lists only that system; tick it, Create → 'System holds Adr' refused, nothing added

## What differs

```text
Expected: Only elements a relation may join are offered, as the connect key's targets (connectTypes leaves holders out)
Actual: Wiki uses…… lists Bookstore (relations stay 4); table lists API (relations stay 4, plus a contradictory 'was linked' warning); ADR wizard lists 1 element, its holder, and Create adds 0 ADRs. The ways also read 'uses……' with the ellipsis doubled
Seen: 2 of 2
Where it probably comes from: guess: WikiView.tsx relationReadingsOf, viewPipeline.ts linkCandidates, metamodel/wizard.ts wizardRelationCandidates do not use holderOf; TableView.tsx linkExisting does not check addRelation's result
A test that would catch it: apps/e2e/tests/studio/wiki.spec.ts + nesting.spec.ts: no holder among the picker's and the ADR wizard's candidates; packages/common/tests: linkCandidates excludes holders
```

## Fixed (2026-10-23)

Add or link, the wizard and the wiki now offer only what relationRefusal accepts, and the table no longer says "was linked" after a refusal.

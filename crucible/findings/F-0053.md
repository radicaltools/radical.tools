## Steps

1. Sample, Presenter: link slide 2 (Core Banking) to milestone v3, F5: 14 drawn
2. Designer, Core Banking: select Payments Service, Delete, Remove from model
3. Presenter: play slide 2 again; or open v3 on Core Banking in Designer

## What differs

```text
Expected: v3 (which still holds Payments Service, Payment Validator and FX Engine) shows Core Banking with 14 elements, as before the delete
Actual: The v3 slide and v3 in Designer draw 11: the three are gone from the view; the saved v3 still holds 3 of 3; Banking Services keeps a frame sized for them
Seen: 2 of 2
Where it probably comes from: guess: packages/common/src/model.ts deleteNode -> forgetNodesInViews / c4.ts removeFromViewList strip the shared views' nodeIds that milestones use too; a milestone holding the element could keep its own view list (DiagramSnapshot.views)
A test that would catch it: apps/e2e/tests/studio/milestones.spec.ts: delete Payments Service on live Core Banking, open v3 on Core Banking (and a v3 slide with F5): ctn-payments, comp-validator and comp-fx are drawn
```

## Decision (2026-10-23)

The user confirmed it is a bug: a milestone shows the model as it was, so a view shown in a milestone still draws the elements that milestone holds, though they were deleted from the current model since.

## Fixed (2026-10-23)

A live delete (Studio, Unwrap, MCP delete_node, or a propagated delete for earlier milestones) now leaves each milestone that holds the element with its own copy of the view's element list (DiagramSnapshot.views, without positions), so the milestone and its slides still draw it.

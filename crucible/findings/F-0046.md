## Steps

1. Sample model, + New view → Blank view, + Start with Step (12 rows)
2. double-click Enter the payment: its card says Repeat 1
3. + Filter offers 'Repeat is 1 · 0' and 'Repeat is not set · 9'; pick Repeat is 1

## What differs

```text
Expected: An element with no stored value reads as its type's default, as the card and the Warnier view show it: Repeat is 1 keeps those 9 steps, 'is not set' does not
Actual: Repeat is 1 → 'No elements pass the view's steps.' (0 of 12, 9 of them reading 1 on their card); a step added now from the + row stores '1' and is the only row it shows; Children run is sequence · 1 against not set · 9 alike
Seen: 2 of 2
Where it probably comes from: packages/common/src/viewPipeline.ts propertyValues / matchesFilter (and suggestFilters, sortNodes) read only the stored value, while meetFilters and the card use the metamodel default (a guess)
A test that would catch it: packages/common/tests/viewPipeline.test.ts: a step without repeat matches {property repeat is 1} and not {repeat unset}; suggestFilters counts it under 'Repeat is 1'
```

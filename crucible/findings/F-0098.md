## Steps

1. Open the sample, view System Context (curved or orthogonal lines)
2. Smart Layout

## What differs

```text
Expected: no relation label over an element after Smart Layout; Tidy keeps the label's drawn width between the two elements or counts the overlap
Actual: before: 0 labels over elements; after: Core Banking Platform and KYC / AML Provider 124 px apart, the label drawn 156x35 (one row) over both (560 px² each); Tidy reports lbl=0.00 and a rerun says already scores best. relationLabelSize estimates it 108x50 (two rows): 'Bulk payments & treasury' 115 vs 159 drawn, 'Views accounts & transfers' 122 vs 160
Seen: 3 of 3 curved, 2 of 2 orthogonal
Where it probably comes from: packages/layout/src/edgeLabels.ts estimateLabelSize: CHAR_EM 0.56 overestimates the glyphs, so a name that fits one row is wrapped into two and the box comes out narrower; used by tidy/cost.ts and by the canvas's labelSpots (edgeGeometry.ts)
A test that would catch it: packages/layout/tests/edgeLabels.test.ts: relationLabelSize of 'Identity & AML screening' [REST / JSON] is at least as wide as the canvas draws it (156); apps/e2e: sample System Context, Smart Layout, no .relation-label box meets an element
```

## Fixed (2026-10-26)

Labels are sized as CSS draws them (one row while the name fits, full width once a line wraps), measured in the drawn font on the canvas and by the font's advance table in layouts (one layout on any machine), so Smart Layout no longer leaves 'Identity & AML screening' over the elements it joins.

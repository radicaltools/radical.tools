## Steps

1. Bookstore fixture, Containers view
2. Double-click API: Parent lists — and Bookstore only
3. Select API, hold Alt: Payment Provider reads 'uses · inside'
4. Drop on 'inside'

## What differs

```text
Expected: 'inside' only where the card's Parent field would let the element go (parentCandidates): not on an external system, not where the move is then refused
Actual: API nested in external Payment Provider (its relation to it removed); group case: Zone reads 'inside', the drop gives 'Action blocked: Cannot move Group "Front" there: its Web App "Web App" would have no place'
Seen: 2 of 2 each
Where it probably comes from: packages/ui/src/components/Canvas.tsx connectTargets: 'inside' uses isPlacementAllowed + holderOf, not parentCandidates/checkReparent in packages/common/src/model.ts (guess)
A test that would catch it: apps/e2e/tests/studio/nesting.spec.ts: with API selected and Alt held, Payment Provider has no 'inside' pill; with a group holding a web app selected, a top-level group has none
```

## Fixed (2026-10-23)

"Inside" (and Move to…) offers exactly where the card's Parent field lets the element go (nestRefusal), never an external element or a group whose contents would have no place; the engine refuses a move into an external element too, so the store and MCP move_node refuse what the card does not offer.

# Step 9 — customer accounts

You now also speak for Jan (customer service) and for the data protection
consultant the company works with.

## Standing requirement (it holds for the whole life of the system)

- **R4, the data protection consultant and Tomek:** the system now keeps
  personal data: names, e-mail addresses, phone numbers, postal addresses.
  A person can ask for their data to be erased, and then it must really be
  gone from everything the system shows. But orders, payments, returns
  (later also invoices) and the stock history are the company's books:
  they are never deleted and never lose their amounts, products or dates.
  They stay, without the person's data. So the person's data has to be
  kept in a way that it can be taken out while the records stay. Nobody
  asks for erasing in this step; the consultant says it when asked about
  customers' data, and it holds from now on.

## Accounts

- An account has a name (required), an e-mail address (required, must look
  like one, kept as typed) and a phone number (optional, free text). The
  system gives it an id. Name, e-mail address and phone can be changed.
- **HD-40:** one account per e-mail address, upper and lower case ignored.
  A second account with an address that is taken is refused; so is changing
  an account to an address another account has.
- An account has any number of addresses. Addresses can be added and
  removed; there is no "default" address.
- **HD-43:** an address is street (with the house number), city, postal
  code and country, all four required. The country is the two-letter code
  in upper case (`PL`, `DE`); anything else is refused. The postal code is
  free text.

## Orders on an account

- An order can name an account. It is then that customer's order. Orders
  without an account stay possible and work exactly as before.
- **HD-41:** an order on an account does not need an e-mail address: it
  carries the account's e-mail address as it was when the order was placed.
  Changing the account's address later does not change earlier orders.
- An order on an account can name one of the account's addresses as where
  it goes. It is optional for now (the agency's checkout will always send
  it). An order without an account has no address.
- **HD-44:** the order keeps its own copy of the address as it was when
  the order was placed. Removing the address from the account does not
  change the order.
- **HD-45:** the address must be one of that customer's own. Another
  customer's address, a removed one or an unknown one: the order is refused
  and nothing is reserved.
- An order on an account that does not exist is refused.
- Jan wants to open an account and see all its orders, in every state.
  **HD-46:** newest first, as in the look-up by e-mail address.
- **HD-42:** orders with the account's e-mail address belong to the
  account, upper and lower case ignored: when an account is opened, the
  orders placed earlier without an account under that address become the
  account's orders, and an order placed later without an account under that
  address is put on the account as well. (Changing the account's e-mail
  address later moves nothing.)
- The look-up of orders by e-mail address stays as it is.

## Not decided

Logins and passwords (the agency does that), merging two accounts, more
than one phone number.

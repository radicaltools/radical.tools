consequences: "The three products have names that explain each other, and the testing loop (Crucible) and the gate (Assay) are told apart. Implementing it touches the CLI (a new command name, help and usage text, the alias), the root npm scripts, the CI job's wording, CLAUDE.md, the manual, the Inspector's labels and the model's requirement and component texts; nothing in check.json or the report formats changes. A second name exists for a while; the alias keeps it harmless."
context: "With Radical Crucible named after Radical Forge's workshop (Forge builds the model, Crucible puts the code to the test against it), the third member, `radical check`, has a plain name that says nothing of what sets it apart: it measures how much of the model is backed by evidence (requirements with scenarios, verified requirements and ADRs, bound tests, each against a goal in percent in check.json) and fails CI below its goals. The maintainer asked for a name in the same style and chose Assay over Hallmark, Touchstone and Gauge. `check` is already used by the CLI command, the CI job \"Architecture model\", `npm run check:architecture`, CLAUDE.md, the manual, Studio's Inspector, check.json and the model's own texts."
date: "2026-10-21"
decision: "The product formerly called radical check is named Radical Assay: an assay tests metal against a standard and grades it in percent, as the check grades the model's evidence against its goals. The family reads as one workshop: Forge builds the model, Crucible searches for where the code breaks it, Assay grades in CI how much of it is proven. The command becomes `radical assay`, and `radical check` stays as an alias for good, so existing CI jobs, scripts and documents keep working; check.json keeps its name. Recorded on 2026-10-21 without a code change: until the rename is implemented the command, the CI job, the manual and the model's texts keep saying radical check."

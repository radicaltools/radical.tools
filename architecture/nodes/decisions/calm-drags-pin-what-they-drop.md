label: "Calm drags pin what they drop"
alternatives: "Keep the physics during drags but damp it or cap how many elements it may move (still moves what the user did not touch, and does not stop the pull-back after the drop); pin without calm drags (the drag itself still shakes the diagram); honour pins in Smart Layout (fixed positions inside ELK and the annealer: a core-IP change that needs its own benchmark; left open); keep pins through Smart Layout at the places it chose (pins that no longer mean \"where I put it\", and never cleared); Alt for the push drag (Alt is the default connection modifier)."
consequences: "Arranging by hand no longer disturbs the rest of a diagram, and a hand-placed element stays put when the physics later runs (a small diagram relaxing, an expand). Pins accumulate with every drop until the next Smart Layout; meanwhile the physics has fewer elements it may move, and an overlap against a pinned element stays. Unpinning is per element (the pin on a selected element), per view (its properties) or by id for agents (remove_alignment). A click is not a drag: React Flow reports one as a drag, so a calm drag starts only once the element moves. Smart Layout output is unchanged; it only clears the pins."
context: "On large canvases with many layout constraints, a drag ran the live WebCoLa physics: dozens of other elements moved during the drag, kept moving for seconds after the drop (measured on this repo's architecture model, 499 nodes: 44 of 45 shown elements moved, the farthest by 27 000 px, still moving 4 s after the drop), and the dropped element was pulled back from where the user put it. Drags are how users arrange a diagram by hand."
date: "2026-10-08"
decision: "A drag on the canvas is calm by default: only the dragged element moves (with the other selected elements React Flow drags along, and the members of its rows and columns, which follow it across the line so the line holds; an ordered line pushes the next member ahead). The physics does not run during the drag. On the drop, elements the moved ones now cover (drawn boxes closer than 24 px) are pushed clear whole, along the axis of least overlap, and whatever they then cover in turn; a container that grew pushes its neighbours the same way; nothing else moves. The dropped elements are pinned: a PinConstraint (LayoutConstraint type 'pin', one per canvas) that the live physics holds like a frozen node, for good. Cmd/Ctrl held at the start of a drag (a key the connection modifier does not use) runs the physics as before. Pins bind the live physics only: a layout of the whole canvas (Smart Layout, the tree layout, the MCP server's smart_layout), run on purpose, places every element anew and removes the canvas's pins in the same undo step; when it keeps the current layout, they stay. This amends \"User alignments bind layout\" (every engine honours every constraint kind) for pins."
status: "accepted"

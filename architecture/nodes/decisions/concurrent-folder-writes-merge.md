label: "Concurrent folder writes merge"
alternatives: "Refuse and reload (the previous decision): loses unsaved edits. CRDTs (Automerge, Yjs): editors, git and agents write the files without CRDT operations, so a diff against the files is needed anyway, the history would be a second, binary source of truth, and Studio's store and undo would be rebuilt; worth it for live multi-user editing, not for two writers. Locks per element or per file: no atomic create in the browser, polling makes them late, and relations, moves and shared sidecars span elements. An operation log: a second source of truth with one process to apply it."
consequences: "An agent and a user can work on the same model at once: changes to different elements or fields both land, nothing is refused for that, and the user's edits survive the agent's. Two changes of the same field keep the folder's, and the writer is told which. The merged model may break a rule the two sides kept alone (a relation to an element the other side deleted); get_issues and Studio's validation show it. A writer that rereads nothing (a text editor) still overwrites, as before. No locks: the browser has no exclusive file create, and the merge makes them unnecessary for two writers."
context: "ADR Folder writes refuse conflicts made a write fail when a file changed outside since the writer read it, and Studio then reloaded from disk, so the outside edit won. With an agent writing the folder over MCP while the user edits in Studio, that lost the user's unsaved edits on every reload and refused the agent's calls whenever Studio saved in between, though the two nearly always change different elements."
date: "2026-10-19"
decision: "A write that finds files changed outside since its read merges instead of failing: mergeModels (@radical/common/modelMerge.ts) takes the model as read (base), the writer's model (ours) and the folder's (theirs), and merges elements, relations, views, sequences, presentations and milestones by id and their fields by key, nested objects (positions) key by key; a field both sides changed keeps the folder's value and is reported (positions and camera silently). MdFolderSession.write takes this merge as an option (mergeMdFolderFiles), which Studio's desktop app and browser and the MCP server pass; a folder that does not read as a model is still refused. Studio, reloading an outside edit while it has edits not saved yet, merges them the same way and saves them after. While the MCP server has written the folder in the last 15 s (.radical/agent-activity.json), Studio holds its saves, shows that it waits for the agent, merges each reload, and saves when the agent pauses. Amended 2026-10-21 (the maintainer's decision D9): an element or relation one side deleted and the other changed is deleted, the delete winning, and a notice names whose change was dropped; an element added into a container the other side deleted brings the container back with its relations and places, with a notice, so no element is lost to a parent that is gone."
status: "accepted"

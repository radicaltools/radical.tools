label: "Properties can reference nodes"
alternatives: "Transitions as nodes with relations to their events: real links, but a statechart stops looking like one, orphaned transitions need cascades, and one transition costs three tool calls. Names as text checked against labels (the first version): a rename breaks the link, and raised events had to be parsed from prose. Relations between relations: a new graph concept for every layout engine, view and file format."
consequences: "A rename of the target never breaks a reference, and the canvas shows the new name at once. Deleting a node leaves the references to it dangling, with a warning in the metamodel editor's Validation list (and from the MCP server) and a marked entry in the picker, until someone removes them. Ids are unreadable in raw files; Studio and search_model show labels. A property's value can now be an array, which code that assumed scalars has to handle (frontmatter, query language, table cells)."
context: "A transition had to name its trigger and the events it raises. A relation can only connect two nodes, so the first version stored the event's name as text: a rename broke the link silently, and events raised in actions were parsed out of prose (`raise OrderPaid`). Making the transition a node would allow real relations, but turns every arrow into a box and two edges, needs cascades for orphaned transitions, and triples the tool calls agents and Forge make."
date: "2026-10-09"
decision: "The metamodel gets a property type 'ref' (packages/common/src/metamodel/refs.ts): `refType` names the node type it points at and `multiple` allows several. The value is the node's id, or an array of ids; files keep it as such (relations.json, and a one-line JSON array in a node's frontmatter). validateModel warns about an id with no node or a node of another type. The AI tools accept ids or tempIds from the same run and refuse a node of the wrong type; the metamodel context tells agents so, and upsert_node_type and the metamodel editor define such properties. Studio picks references with one component (RefPicker: a list, or chips to add and remove) in the properties panel, the table, the wiki and the node wizard, and shows the nodes' labels. search_model matches a list when one of its ids does. Transitions use it: `event` (one) and `raises` (several) point at event nodes."
status: "accepted"

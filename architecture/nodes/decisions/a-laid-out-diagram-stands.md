Relations that end on an open container still have no force in the physics; an element on the canvas with only such relations is drawn back next to them when the physics runs (holdByGroups), through free room only. Amended 2026-10-13 after exploratory runs 2 and 3: an open container keeps the frame the model has until one of its leaves moves against the others (a drag or an added element elsewhere used to re-frame every open container to the physics' padding); and the physics imposes its C4 order (people above everything else, external systems to the right) only when it arranges a diagram (first start, relaxLayout). On a diagram that has a layout it keeps that order only where the layout has it: imposed there, the first element the physics was free to move was thrown across the diagram (a system dropped after a push drag on a 150-element grid ended up 3 400 px below it). Amended 2026-10-14 after exploratory runs 4 to 6: a collapse moves nothing at any diagram size. A container that is collapsed turns from a frame around others into one box; the engine took that box for a new element and freed the 40 elements nearest to it, which reached into other containers whose frames and other children stayed fixed (in a model nested four levels deep one collapse left 17 to 41 elements moving two minutes later, with containers overlapping). Amended 2026-10-14 after run 11: the relaxed candidate is scored with its containers fitted to their children, as applying it fits them. Scored with the physics' own frames, the winner on the sample's All elements scored better than what was saved, so every later Smart Layout reported an improvement, moved nothing and left an empty undo step. Amended 2026-10-14 after exploratory run 19 (150 to 600 elements): an expand is no longer left to the physics. decision: "A diagram that has a layout keeps it. The live physics takes the positions it is given on every rebuild (open, view switch, undo, milestone, Smart Layout) and moves nothing; it moves only nodes that are new since the previous build (added, or shown by an expand) with their nearest surroundings, at every diagram size, as it already did from 150 nodes up. The members of an alignment or grid just made, which the store snaps onto their line, settle the same way: they and their surroundings move, the rest stays. The physics still moves a whole diagram in three cases, all below 150 nodes: to arrange one that has no layout yet (first start), during a push drag (Cmd/Ctrl), which asks for it, and as relaxLayout: the same physics run over a whole diagram in one go, counted in steps, not time. Smart Layout scores relaxLayout of its winner as one more candidate and keeps it only when it scores better than the winner. The engine (LiveColaEngine, relaxLayout) moves from @radical/ui to @radical/layout, which gains webcola, d3-dispatch, d3-timer and d3-drag as dependencies, so the MCP server's smart_layout computes the same candidate; its build bundles them. This amends \"Graph views use Smart Layout\": no physics pass follows Smart Layout on a model's canvas any more. The metamodel editor's diagram keeps its own pass (relaxLive, animated): it is laid out anew each time it is drawn, and Smart Layout alone spreads its category frames over a mostly empty canvas."

label: "Undo belongs to Designer"
alternatives: "Put the metamodel into every history entry (undoing any step would also take back every metamodel edit made since, as views used to be taken back). Clear the whole history when a type is deleted (loses steps that are still valid). Give Viewer its own undo stack (it has nothing to keep). Keep Restore to live as \"show this milestone\" (that is what clicking a milestone already does)."
consequences: "A session in Viewer or Presenter cannot change the saved model except for the slides managed in Presenter. Edits Designer made in a milestone and had not yet kept or dropped survive a visit to Viewer; Viewer browses milestones without being asked about them. Undo history shrinks when a type is deleted (the steps from before the type's last element went are gone). The metamodel itself is still not undoable. Typing in a properties field is still one step per key (open, see docs/IMPROVEMENTS.md). Amended 2026-10-14 after exploratory runs 7 to 12: a presentation playing (also one started by F5 in Designer, where the perspective stays Designer) saves nothing, since the store holds what its slides show; leaving Designer first puts the canvas's positions and camera into its view, so a save asked for in Presenter writes Designer's current layout; deleting with the Delete key and everything one Hub \"Add to Model\" brings in (parts that arrive one after another) are one step each (_asOneStep, _mergeStepsSince). Amended 2026-10-14 after exploratory runs 13 to 24: the Delete key works in Designer only and not while a presentation plays (it opened the delete prompt there and hid the element from the view for good); deleting the selection from the action bar is one step (removeNodes); applying a Hub template's values again is one step that rewrites only the fields holding a {{KEY}} and also takes back the template record (applyHubTemplate; it was one step per imported element and overwrote renames); an edit that changes nothing (a table cell opened and left) makes no step; Ctrl/Cmd+Z and F5 do nothing to the model while a dialog or a wizard is open (undo took back the element a wizard was creating a child in). A view's UI state (its treemap and wiki focus, the table's tab) is not part of a step: undo keeps the one on screen. A view whose elements were all deleted stays empty (DiagramView.empty) instead of turning into a view of every element."
context: "Exploratory runs 4 to 6 (2026-10-13) found that what Viewer and Presenter do reached Designer and the saved model. Leaving Designer set aside the nodes, relations, views and positions, but not which milestone was shown nor the live model behind it: a milestone picked in Viewer stayed \"the one shown\" in Designer over the live model's nodes (a drag and Propagate then copied the live model over all four milestones of the sample), \"Current (live)\" picked in Viewer left a milestone's 11 elements as the live model of 65, and a slide added in Presenter while a milestone was shown saved the milestone as the live model. Ctrl/Cmd+Z worked from anywhere: in Viewer and Presenter it took one of Designer's steps unseen, and in a text field it took the model's last step instead of the typing. Several edits pushed no undo step (adding, renaming, deleting a view or a sequence, every edit of a sequence's steps), yet a history entry carried the views, so undoing another step added or deleted views; \"Wrap into\" pushed one step per wrapped element plus one. The metamodel is not part of a step, so Undo brought back elements whose type had been deleted since."
date: "2026-10-14"
decision: "Viewer and Presenter are for looking. Leaving Designer sets aside everything Designer shows (nodes, relations, sequences, views, positions, the active view, the milestone shown with the live model behind it, its unsaved-edits flag and the diff), and the return puts all of it back (ParkedDesigner, window.__preModeLayout). A save made while exploring (a slide added in Presenter) writes the live model of the Designer that was left (parkedLiveModel) and its views, never what is on screen. Undo and redo exist in Designer only: the store refuses both elsewhere and takes no step for what is done there, the milestone history swap happens only in Designer, and the keyboard shortcut is left to a text field that has the focus. Every action of the user is exactly one step: view and sequence edits push one, a history entry always carries the sequences, and an action made of several store actions runs as one step (_asOneStep: Wrap into, Quick Search opening several containers). \"Restore to live\" makes a milestone the live model with no milestone shown, as one step of the live model's history. When the metamodel loses a type, the steps that hold elements or relations of it, and every step beyond them, are dropped; replacing the metamodel (Reset to C4 preset) is refused while the model holds elements or relations the new one has no type for."
status: "accepted"

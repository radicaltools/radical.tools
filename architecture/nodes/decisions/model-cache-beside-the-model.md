type: "adr"
label: "Model cache beside the model"
alternatives: "A database as the source of the model: breaks Local-first plain files (git diffs, agents and editors writing files) and the merge of concurrent writers (ADR Concurrent folder writes merge), which works on files. SQLite as the cache: a native or WebAssembly dependency in every host for what one JSON file does at 20,000 elements; worth it if models reach hundreds of thousands. A cache in the browser's IndexedDB: not shared with the desktop app, the MCP server and the CLI, and kept per browser. No cache: opening stays bound by reading thousands of files."
consequences: "Opening a folder whose cache is current reads one file instead of one per element; after a pull or an agent's edits only the changed files are read; the first open of a folder reads all of them and Studio or the MCP server writes the cache in the background. The cache takes about as much disk as the model. A file changed without a new stamp (same modification time and size) would be taken from the cache: the session's polling already assumes stamps change with content. Two writers may rewrite the cache at once: each writes a file beside it and renames it in, the last one wins, and a cache out of date is caught by its stamps. Deleting .radical/cache is always safe."
context: "A model folder keeps one Markdown file per element (ADR Local-first plain files), which is what git diffs and agents and editors write. Opening a folder of 21,000 files, Studio spent about 2.7 s waiting on the files even when reading 32 at a time, and the MCP server and the CLI read every file on every call; after a git pull that changed ten files, all 21,000 were read again. Most of that is reading many small files, not parsing them."
date: "2026-10-30"
decision: "Each model folder also keeps a cache of itself in one file, .radical/cache/model.json (out of git, as all of .radical/): its format version and, for each model file, its stamp (modification time and size) and content, with room for indexes derived from them. It is derived and never the source: the Markdown files are. Everything that reads a folder reads it through MdFolderSession (Studio's desktop app and browser, the MCP server, the CLI): it lists the files' stamps, takes from the cache each file whose stamp matches and reads only the others. Studio opens a folder as its cache has it, without listing the files first (the user's choice, 2026-10-30): the stamps in the cache count as the ones last seen, so Studio's poll of the folder (every second in the desktop app, every two in the browser) finds what changed since and reloads it as any outside edit; a write always compares with the files first. The MCP server, which reads the folder afresh on every call, always lists the files. Studio and the MCP server write the cache again when they found it missing, unreadable, of another format, or out of date by more than 50 files or 1% of the folder; the CLI only reads it, as it exits as soon as it is done and in CI no one would read what it wrote. Saves do not rewrite it: a file a save wrote is read again at the next open. Only a folder holding a model (a valid radical.md) gets a cache."
status: "accepted"

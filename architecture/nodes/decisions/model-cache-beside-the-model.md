label: "Model cache beside the model"
alternatives: "A database as the source of the model: breaks Local-first plain files (git diffs, agents and editors writing files) and the merge of concurrent writers (ADR Concurrent folder writes merge), which works on files. SQLite as the cache: a native or WebAssembly dependency in every host for what one JSON file does at 20,000 elements; worth it if models reach hundreds of thousands. A cache in the browser's IndexedDB: not shared with the desktop app, the MCP server and the CLI, and kept per browser. No cache: opening stays bound by reading thousands of files."
consequences: "Opening a folder whose cache is current reads one file instead of one per element; after a pull or an agent's edits only the changed files are read; the first open of a folder reads all of them and Studio or the MCP server writes the cache in the background. The cache takes about as much disk as the model. A file changed without a new stamp (same modification time and size) would be taken from the cache: the session's polling already assumes stamps change with content. Two writers may rewrite the cache at once: each writes a file beside it and renames it in, the last one wins, and a cache out of date is caught by its stamps. Deleting .radical/cache is always safe."
context: "A model folder keeps one Markdown file per element (ADR Local-first plain files), which is what git diffs and agents and editors write. Opening a folder of 21,000 files, Studio spent about 2.7 s waiting on the files even when reading 32 at a time, and the MCP server and the CLI read every file on every call; after a git pull that changed ten files, all 21,000 were read again. Most of that is reading many small files, not parsing them."
date: "2026-10-30"
decision: "Each model folder also keeps a cache of itself in .radical/cache/ (out of git, as all of .radical/). model.json holds its format version and, for each model file, its stamp (modification time and size) and content; changes.json, the files written or read since model.json was written, so the cache keeps up with saves without rewriting it whole; views.json, an index of the elements each view's filter gives, valid for the model's structure (each element's type and parent, each relation's ends and type) and kept only for views whose filters read nothing else. It is derived and never the source: the Markdown files are. Everything that reads a folder reads it through MdFolderSession (Studio's desktop app and browser, the MCP server, the CLI). The MCP server and the CLI list the files' stamps, take from the cache each file whose stamp matches and read only the others. Studio opens a folder as its cache has it, then lists the files at once and saves nothing until it has; when any differs from the cache it loads the folder afresh from its files, and an edit the user made meanwhile is merged into them. Studio and the MCP server write model.json again when it is missing, unreadable, of another format, or out of date by more than 50 files or 1% of the folder; Studio writes changes.json after its saves and reads, and views.json once it has worked out the views of a structure the index does not have; the CLI only reads. Only a folder holding a model (a valid radical.md) gets a cache. Amended 2026-10-30 (the user's decisions): opening as the cache has it was first done without keeping the cache up with Studio's saves and with the reload that keeps the open canvas's places, which showed and saved old places; it now loads afresh when the files differ, and the cache keeps up with saves."
status: "accepted"

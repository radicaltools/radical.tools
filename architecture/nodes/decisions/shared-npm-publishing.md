label: "Shared npm publishing"
alternatives: "Keep separate MCP and CLI publishing workflows: duplicates the same release procedure and lets checks drift. Keep two entry workflows calling a composite action or reusable workflow: shares implementation but retains multiple entry points and publisher configuration names for this small release flow. Publish packages only from developers' terminals: avoids a workflow but loses the common GitHub release checks and OIDC release path."
consequences: "One workflow holds the npm release procedure, so fixes and validation changes apply to both packages. A release still selects one package; versions, published artifacts and npm permissions remain independent. A workflow change can affect both packages and must preserve both package selections. Existing Trusted Publisher entries naming mcp-publish.yml or cli-publish.yml must be replaced with entries naming npm-publish.yml after migration; pushing the workflow does not update npm settings. Each new package must exist before its package-level publisher is configured, and a new publisher requires its first successful release within two days; a dry run does not validate it. Initial publication can be bootstrapped interactively from a reviewed commit, followed by automated releases of new versions."
context: "The repository publishes the MCP server as @radicaltools/mcp and is preparing the CLI as @radicaltools/cli. Separate mcp-publish.yml and cli-publish.yml workflows duplicate dependency installation, workspace checks, type checking, tests, tarball verification, artifact upload and npm publishing. Maintaining separate copies risks different release checks and publishing settings for the two packages."
date: "2026-10-17"
decision: "Maintain one GitHub Actions workflow for npm releases: .github/workflows/npm-publish.yml, named Publish to npm. Run it manually with a package choice of mcp or cli; mcp is the default and dry-run defaults to true. Share installation, workspace boundary checks, type checking and tests, then run the selected workspace's test:package script with --out-dir ../../release. Upload and publish only that package's verified tarball. Actual publishing is allowed only from main and uses npm Trusted Publishing (OIDC) with provenance; serialize runs per package. Branch pushes and desktop release tags do not publish npm packages. Configure a Trusted Publisher separately on each npm package, using radicaltools/radical.tools and npm-publish.yml. This amends only the separate MCP workflow choice in Public MCP distribution and MCP npm organization; their package identity, bundling and installability decisions remain in force. This decision covers npm releases, not the repository's other CI or deployment workflows."
status: "accepted"

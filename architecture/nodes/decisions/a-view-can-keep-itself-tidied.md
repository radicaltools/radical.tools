label: "A view can keep itself tidied"
alternatives: "Tidy only round the change (Tidy around): the rest never moves, but the whole drifts out of shape as the model grows. A Studio-wide switch for the session, not saved: a view being built and a hand-drawn view need different settings, and an agent could not switch it on. Playing Tidy's moves one by one: slow on a growing model; the user dropped that playback on 2026-10-24. Moving dropped elements too: what the author places by hand would be taken back."
consequences: "On such a view the rule of \"A laid-out diagram stands\" is lifted by the author's choice: elements other than the added one move after an add. Views without the setting are unchanged. A change made while Tidy runs makes it run again when it ends, so a burst of adds ends with one more run. The MCP server does not tidy by itself; Studio does when it reloads the folder, so a model edited by an agent with Studio closed is tidied when it is next opened with a change. Tidy's budget bounds a run on a large view; each change runs it again from where the last one stopped."
context: "\"A laid-out diagram stands\" keeps every layout as it is: an added element stays where it is dropped, and only Smart Layout, run by hand, arranges the view again. While a model is being built that means running Smart Layout after nearly every add. Tidy (\"Smart Layout tidies as a person does\") starts from the canvas and moves only what gains, so a view that is already tidy changes little when it runs again."
date: "2026-10-26"
decision: "A view can have continuous layout switched on (continuousLayout on the view, saved in the model; a switch beside Smart Layout and in the view's properties; create_view and update_view take it). While it is on, Studio runs Tidy over the whole view, in its worker, shortly after each change to what the view shows (an element or relation added or removed, a move to another parent, a collapse or expand, a drop), also when the change is an agent's that Studio reloads. Pinned elements stay where they are (a drop pins, so what the author places stays put and the rest is arranged round it); a Smart Layout run by hand still unpins. The result glides in: the elements move from where they were to their new places in one short animation, not move by move. The tidying joins the undo step of the change that caused it. An undo, a redo, a view switch, opening a model and a change of positions only start nothing. Tidy is the engine whatever the view's Auto-layout setting says; a tree or ensemble view keeps its own Smart Layout button."
status: "accepted"

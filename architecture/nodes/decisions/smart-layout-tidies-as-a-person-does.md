alternatives: "Keep the ensemble and calibrate its ranking on the author's judgements: a ranking chooses among whole layouts and cannot explain or take back one choice. The semantic grid (feat/radical-grid): right on small views, wrong on large ones, and as opaque. Simulated annealing over the same moves: random, so the moves it takes cannot be read as a person's."
consequences: "The result depends on the canvas Smart Layout starts from, as a person's does, and is the same every time for the same canvas; a second run continues where the first stopped and may change nothing. Views laid out from a pile of elements get a layout that is only as good as the moves reach from it; the set of moves grows from what the author corrects (layout lessons). Screenshot baselines of laid-out views change. The ensemble and its ranking stay reachable per view. Boxes stand on a 1/1024 px grid and the closing passes (lines drawn in, judged afresh, the margin) repeat until one changes nothing, so a second run on Tidy's own layout finds nothing left to tidy (round 185–192, 2026-10-26, F-0074). The budget is counted in work (moves judged, each weighted by the view's elements), not time: Studio and the MCP server give a run the same budget (TIDY_BUDGET), so a view gets the same layout on any machine and from either (F-0080). Tidy runs again on its own layout and takes what that run finds, until a run finds nothing, so the next Smart Layout finds nothing either (F-0107), and it lines up the author's rows and columns only where they are off, handing over exactly the layout it judged (F-0106, F-0108); a run takes about a fifth longer (round 193–200, 2026-10-26). Layout decisions size labels by the UI font's advance table, never the drawn font, so a view gets one layout on any machine and from the MCP server."
context: "Smart Layout computed a whole layout at once: twelve engines, each a layout of the entire view, ranked by a standardised score, the two best refined by simulated annealing. On the author's own views the pick kept coming out wrong: elements spread three times wider than needed, lines slanting where a row would do, decisions far from what they constrain, and no way to say which choice was wrong, because there was no sequence of choices, only a winner. An attempt at a semantic grid (one global layering, columns per container) reproduced the author's small views and lost on larger ones, and again gave no handle to correct it. What the author does by hand is a sequence: take the diagram as it is, pull a database out beside its service, put the person on top, swap two boxes whose lines cross, slide a box until its line runs straight, centre a box over what it relates to, close a gap, and stop when nothing is left to do. The people in the HOLA study (Kieffer, Dwyer, Marriott, Wybrow, TVCG 2016) did the same: leaves outside, rows and columns, symmetry, fewer crossings, bends and long lines. Dunnart (Dwyer, Marriott, Wybrow 2009) lets a person make such moves with the layout keeping the rest in place, and Davidson and Harel (1996) cost a layout by crossings, lines over elements and even spread, improving it move by move."
date: "2026-10-23"
decision: "In the Auto mode (the default) Smart Layout runs Tidy: it starts from what is on the canvas and improves it one move at a time, taking in each round the move that lowers the reader's cost most (crossings first, then lines over elements, slanting lines, long lines, an element off the middle of what it relates to), and stops when no move lowers it. The moves are the ones a person makes: a store with one user or a note with one relation pulled out beside it, an actor put above what it uses, an outside system put below or right of what calls it, two neighbours swapped, an element slid along its row or column until a line runs straight, an element centred over what it relates to. No move leaves two siblings on each other or a child outside its container; frames follow their children. Studio shows the result at once; Why this layout? lists the moves in order with what each gained, so the author can say which move was wrong (playing them one by one was tried and dropped: it only slowed the author down). The twelve-engine ensemble stays as the view's auto-layout mode Ensemble."

label: "Forge models the domain first"
alternatives: "After the scenarios, next to the state machines (the scenarios would invent their own nouns first). Inside the C4 stage (domains would follow the decomposition instead of shaping it). Entities nested in their aggregate root by containment (an aggregate's parts would hide inside a card, and containment cannot express references). The domain model only in the Domain view (the owner wants it in Conceptual for now)."
consequences: "One language runs through a run, and the State machines and C4 stages link to elements that already exist instead of creating duplicates. A run has seven stages; the wizard's step bar fits nine steps on one line only with short labels (Fitness, C4) and tight pills. The domain model shows twice (Domain and Conceptual) until Conceptual drops it. Entities have no attributes or value objects yet."
context: "Each Radical Forge stage named things its own way: scenarios, state machines and C4 each made up the nouns of the system, and the State machines stage created entities of its own. The metamodel had domains and entities but no relations between entities, and no stage built a domain model, although DDD's ubiquitous language is what the later stages should share."
date: "2026-10-09"
decision: "A Domain model stage runs right after Requirements and before Fitness functions: Requirements → Domain model → Fitness functions → Gherkin scenarios → State machines → Mockups → C4 model. It adds `domain` nodes (bounded contexts, kind core/supporting/generic) holding `entity` nodes in the requirements' words, groups entities into aggregates with a new `part-of` relation (entity → aggregate root), links aggregates with a new `references` relation (entity → entity, cardinality one or many), maps the domains with `depends-on` and `partnership`, and links each entity to its requirements with `satisfies`. Later stages use it: scenarios name its entities, the State machines stage takes its entities (adding one only when missing), and C4 adds `realises` to domains and entities. Its output goes into a new Domain view and, at the owner's request, also into Conceptual; a type may now go into several Forge views. @radical/common's domainModel.ts warns about entities outside any aggregate, parts of two aggregates, parts of a non-root and roots inside another aggregate."
status: "accepted"

type: "adr"
label: "Groups hold what their place allows"
alternatives: "A transparent group (only the nearest ancestor that is not a group counts, by allowedParents alone): refuses a component in a group inside a system, which ADR Groups inside a system allows on purpose. A new field on a node type naming the ancestor it needs: one more thing to keep right in every preset, the metamodel editor and the file format, for a rule that follows from the fields already there. Leaving the rule and only hiding the types in the wiki: the canvas, the table and the MCP server would still allow it."
consequences: "A group at the top of the model no longer takes containers, components, databases, web apps or queues; a group inside a system still does, so the shared packages of this model stay where they are. A group inside a system no longer takes a person, a domain, an entity or a blueprint. A model that already holds such an element keeps it and gets a warning in the Validation list (bad-place), not an error. None of the 260 bundled models and Hub concepts nor the sample holds one. Custom metamodels get the rule too, for their type with the id group."
context: "Every C4 part lists the group among its allowed parents, so that a group can gather parts of a system (ADR Groups inside a system). The metamodel checked only the type of the direct parent, so a group gave a place to anything that names it: a component, container, database, web app or queue could be put into a group at the top of the model, where none of them may be, and a person or a domain into a group inside a system. Writing in the wiki made it one click: a new, empty group offered every such type."
date: "2026-10-13"
decision: "A group gives no place that an element could not have without it. A type that lists the group among its allowed parents may sit in a group only if the place where the group stands has room for it: at the top of the model, the types allowed at the root; under an element (the group's nearest ancestor that is not a group), the types that element can hold directly or deeper down by the allowed parents of the types in between. The rule is derived from allowedParents and allowedAtRoot, with no new field in the metamodel (isPlacementAllowed, hasPlaceUnder and placeOf in packages/common/src/metamodel/lookup.ts). It applies to adding, moving and retyping a node, to wrapping and unwrapping, and to moving a group, which is refused where what it holds would have no place. The wiki, the table, the selection bar and the Hub import offer only what the rule allows."
status: "accepted"

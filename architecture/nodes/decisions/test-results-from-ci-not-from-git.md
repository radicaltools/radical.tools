type: "adr"
label: "Test results from CI, not from git"
alternatives: "Committing test-results.json: a commit cannot hold the results of its own tests, so the file in git would always describe an earlier commit while git presents it as current; it is also 550 KB of runner paths changing on every run, noise and conflicts in every merge. Git notes written by CI: no GitHub API needed and any CI could write them, but notes need a fetch refspec on every clone, CI needs write access, and the repository grows with every commit. A Fetch from CI button in Studio: the web build cannot run gh, so only the desktop app or an agent could use it; it can come on top of the CLI."
consequences: "The Inspector shows results tested by CI for the commit checked out or the one before it, and says which commit and run and how many commits HEAD is past it. Fetching needs gh, signed in, and a GitHub remote; without them the hooks do nothing and radical check --from-ci says what is missing. Other CI services need an adapter of their own. Artifacts expire (14 days here), so an old branch may find no results. A pull request run tests the branch merged into main as it was then, which may differ slightly from the squash commit on main."
context: "Studio's Inspector reads the test results kept in the model folder's .radical/test-results.json, out of git. They were only as fresh as the last radical check --report on the developer's machine: the full suite, e2e included, takes long to run locally, so the results were often days old, and the Inspector showed every test added since as missing. CI runs every suite on every pull request and keeps the reports as artifacts. The product owner asked whether the results should be committed instead (2026-10-31)."
date: "2026-10-31"
decision: "Test results are never committed. radical check --from-ci downloads the test reports of the latest CI run of the nearest commit in HEAD's history that CI ran, through the GitHub CLI (gh): a commit merged from a pull request (a squash merge has no run of its own) stands for the head of that pull request. The results kept beside the model name the commit they belong to and the runs they come from, and results read locally at a later commit are never replaced by older ones from CI. The git hooks radical hooks installs fetch them in the background after a checkout, a commit, a pull and a rebase, so the Inspector has the results of CI without anyone running a command."
status: "accepted"

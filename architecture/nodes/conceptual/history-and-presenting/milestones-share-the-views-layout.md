type: "requirement"
label: "Milestones share the views' layout"
action: "Studio shall show each view with one layout for the live model and every milestone: its name, folder, places, camera, folds, line style, alignments, filter and every other setting are shared, and a milestone keeps of a view only what it shows another way (its element list where it holds elements deleted since, the sequence link of a flow view whose sequence was deleted since, the view edits Save as new kept in it, and the view of an element deleted since, whole with its places), everything else following the live view, also edits made on it later; show All elements with the milestone's own positions, and save none of the milestone's positions into the live views or the live All elements; take what is done on a view (a move with Move to…, a collapse, Hide from view, an alignment, pins and Unpin all, its filter, Multi page, and its viewpoint, Auto-layout, Sequence, view type, Size and Levels) as an edit of the milestone: asked about as a drag is, kept out of the live views and the live All elements, kept when a change made outside Studio is read, taken back by Discard, kept in the new milestone by Save as new (reopening it shows them, after a reload too) while the live views and other milestones stay as they were, and made by Propagate the live view's and every later milestone's, carrying only what was edited; and show the live layout of the canvas shown when the milestone is left, keeping or carrying on the milestone's edits with its All elements positions, whichever view is open. A view's name, folder and order, and adding or deleting a view, stay shared with the live model: a view renamed or moved to another folder, or a folder renamed, while a milestone is shown is renamed in the live model, saved so, and kept when the milestone is left or its edits are propagated. When an element a milestone holds is deleted from the live model (in Studio, by Unwrap, by delete_node, or by a delete propagated from an earlier milestone), each milestone that holds it shall keep its own list of the view's elements, and the element's own view in a group of views per element whole, with its places, in its group, shown in that milestone alone and never saved with the live views, so that it and its slides still draw the element; when a sequence a milestone holds is deleted (in Studio, by delete_sequence, or by a delete propagated into the milestones before), its flow views shall stay linked to it in each milestone that holds it, so they still play it there; Restore to live shall make the milestone's view lists and its own views, with their places, the live ones; and a slide of a milestone shall play that milestone's views wherever it is shown, also after a reload."
ears_type: "state-driven"
precondition: "a milestone is shown in Designer"
rationale: "One layout per view puts an element in the same place in every milestone, so comparing two shows only what changed. Switching views while a milestone was shown saved the milestone's positions into the live view, and keeping its edits with a view open carried that view's layout into the live model as changes (2026-10-14). The maintainer decided on 2026-10-21 (D1, exploratory runs 45 to 64) that layout edits made while a milestone is shown are edits of the milestone, as the manual says: a collapse, Hide from view, an alignment or Move to… in a milestone had changed the live view for good. Exploratory runs 65 to 69 (2026-10-21, item 230) found a viewpoint, Auto-layout, Sequence, view type, Size or Levels set in a milestone still changing the live view, and the maintainer decided that Save as new keeps the view edits made in the milestone in the new one. A live delete took the element off the shared view list, so a milestone that holds it no longer drew it (run 184, 2026-10-23, F-0053); the maintainer decided that a milestone shows the elements it holds, also when they have been deleted from the live model since. In round 185–192 (2026-10-26) a milestone lost the view of an element the live model deleted (F-0064), a deleted sequence unlinked its flow views in every milestone (F-0065), and a view renamed while a milestone showed its own copy changed only the copy, splitting its folder in two (F-0066). In round 193–200, 2026-10-26 a milestone that kept its own list of a view kept the whole view, so a fold or line style set later on the live view never reached it and Propagate missed the later milestones (F-0089); Propagate put the milestone's whole copy over the live view, dropping what was added and folded there since and listing what it had deleted (F-0091); Restore to live left the deleted element off the views that listed it (F-0090); a slide of a view the milestone has alone drew nothing (F-0103); the MCP presentation tools and radical check judged a milestone's slide by the live views (F-0104); and an outside change dropped the milestone's unsaved view edits (F-0105). One rule now decides it: a milestone keeps of a view only what it shows another way. Evidence: packages/common/src/model.ts (milestoneView, milestoneViews, milestoneOwnView, viewEdited, milestoneOnlyView, keepViewsInMilestones, keepSequenceViewsInMilestones), packages/ui/src/store/diagramStore.ts (setActiveView, selectMilestone, discardMilestoneChanges, commitMilestoneChanges, _milestoneViewEdit, showMilestoneViews, propagateViewEdits, restoreMilestoneViews, keepMilestoneViewEdits, slideViewsOf, parkedAsShown, liveBackup.views, _saveShownCanvas, _showLiveCanvasPositions), packages/common/src/ai/tools/presentationTools.ts (parseSlides), packages/common/src/check/index.ts (staleReferences), packages/common/src/c4.ts (DiagramSnapshot.views, MilestoneView)"

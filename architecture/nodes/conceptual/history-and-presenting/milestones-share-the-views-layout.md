type: "requirement"
label: "Milestones share the views' layout"
action: "Studio shall show each view with the layout it has for the live model and every milestone, show All elements with the milestone's own positions, save none of the milestone's positions into the live views or the live All elements, and take what is done on a view (a move with Move to…, a collapse, Hide from view, an alignment, pins and Unpin all, its filter, Multi page, and its viewpoint, Auto-layout, Sequence, view type, Size and Levels) as an edit of the milestone: asked about as a drag is, kept out of the live views and the live All elements, taken back by Discard, kept in the new milestone by Save as new (reopening it shows them, after a reload too) while the live views and other milestones stay as they were, and made the live views' by Propagate; and show the live layout of the canvas shown when the milestone is left, keeping or carrying on the milestone's edits with its All elements positions, whichever view is open. A view's name, folder and order, and adding or deleting a view, stay shared with the live model When an element a milestone holds is deleted from the live model (in Studio, by Unwrap, by delete_node, or by a delete propagated from an earlier milestone), each milestone that holds it shall keep its own copy of the view's element list, without positions, so that it and its slides still draw the element."
ears_type: "state-driven"
precondition: "a milestone is shown in Designer"
rationale: "One layout per view puts an element in the same place in every milestone, so comparing two shows only what changed. Switching views while a milestone was shown saved the milestone's positions into the live view, and keeping its edits with a view open carried that view's layout into the live model as changes (2026-10-14). The maintainer decided on 2026-10-21 (D1, exploratory runs 45 to 64) that layout edits made while a milestone is shown are edits of the milestone, as the manual says: a collapse, Hide from view, an alignment or Move to… in a milestone had changed the live view for good. Exploratory runs 65 to 69 (2026-10-21, item 230) found a viewpoint, Auto-layout, Sequence, view type, Size or Levels set in a milestone still changing the live view, and the maintainer decided that Save as new keeps the view edits made in the milestone in the new one. A live delete took the element off the shared view list, so a milestone that holds it no longer drew it (run 184, 2026-10-23, F-0053); the maintainer decided that a milestone shows the elements it holds, also when they have been deleted from the live model since. Evidence: packages/ui/src/store/diagramStore.ts (setActiveView, selectMilestone, discardMilestoneChanges, commitMilestoneChanges, _milestoneViewEdit, milestoneOwnView, showMilestoneViews, liveBackup.views, _saveShownCanvas, _showLiveCanvasPositions), packages/common/src/c4.ts (DiagramSnapshot.views)"

type: "requirement"
label: "Views of a viewpoint"
action: "Studio shall make the view one of that viewpoint, with its view type and a copy of its filter chain (a new view named after it), show under the list what the viewpoint shows, show the chain read-only (Set by the viewpoint) with Detach, which keeps the view type and chain for the view alone as None in the list does, bring every view of the viewpoint in step when the metamodel changes it, leave such views their view type and chain, of no viewpoint, when it is deleted, asking first, and listing them, when that deletes a group's views per element (also when the types it draws a view of each element of are taken away), Undo bringing them back, and leave the viewpoint when the user picks another View type or sets another chain."
ears_type: "event-driven"
rationale: "Views that answer the same question (traceability, coverage, decisions) are set up the same way in every model, and stay the same when the team changes how that question is asked; the name follows ISO/IEC 42010, where a viewpoint sets how views for a concern are built, and keeps View type for Structure, Flow, Hierarchy, Table, Matrix and Wiki. The Radical metamodel brings Traceability, Requirement coverage and Decisions, all tables. A document on a built-in preset keeps its own viewpoints when the preset is swapped in on load. Deleting a viewpoint whose views were a group deleted them without asking (run 183, 2026-10-23, F-0052); the maintainer decided that it asks first and lists the views. Evidence: packages/common/src/viewpoints.ts, packages/common/src/model.ts (applyViewpoint, syncViewpoints, setViewKind, setViewPipeline, documentMetamodel), packages/common/src/metamodel/presets/governance.ts, packages/ui/src/store/diagramStore.ts (applyViewpoint, addViewOfViewpoint, detachViewpoint, _syncViewpoints), packages/ui/src/components/RightPanel.tsx, packages/ui/src/components/ViewPipelinePanel.tsx (ViewpointRow), apps/studio/src/renderer/src/components/MetamodelEditor.tsx (ViewpointCard, groupLosses); manual#viewpoints"
trigger: "the user picks one of the metamodel's viewpoints under + New view or in the Viewpoint list of a view's properties (marked from the metamodel)"

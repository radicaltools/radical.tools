type: "requirement"
label: "Node discussions in folder models"
action: |
  Studio shall offer Discuss on any graph node with a persistent ID in a desktop folder model or a connected browser folder model, opening one reusable panel pinned to that node with separate session drafts; create open threads, replies to any comment and resolve/reopen actions in discussions.json beside the model, using UUIDs and UTC timestamps, optional editable email remembered best-effort on the device and saved as an attribution snapshot with the shared comment, otherwise Anonymous; preserve attachment by node ID across rename, move, type changes, deletion and restoration, retain missing-node threads and leave new IDs without inherited threads; validate the complete structure, serialize participating writers and atomically replace the latest valid file after applying an action; acknowledge writes before confirming success and check uncertain submissions by ID and content before a manual retry; retain drafts and the last valid view on failure, require review of stale thread state, block overwriting unreadable or unexpectedly missing files, and refresh discussions independently without changing model data, dirty state, undo, layout, exports or folder pruning; render Markdown safely, preserve readable ancestry with capped indentation and support keyboard navigation; explain that an unsaved node must be saved to retain its attachment.
  Nodes with existing threads shall show a clickable discussion icon at the top-right corner, including resolved threads, with thread/open counts in its accessible label and tooltip; markers refresh while the panel is closed and remain outside model data and diagram exports.
  Discuss shall also be available on table node rows and wiki node pages, headings, navigation entries and references, sharing the exact target node's threads and session drafts across views; Viewer shall allow discussions while keeping model edit actions unavailable, text editors and ordinary web links shall retain native menus, and hosts without folder discussion support or presentation playback shall offer no discussion action.
ears_type: "ubiquitous"
rationale: |
  First release of the broader Discussions on model objects need, narrowed by radical-tools-discussions-simple-plan.md (2026-10-25), extended at the user's request to browser folders. The browser uses File System Access and Web Locks; same-origin tabs share a write turn and browser/desktop intent markers coordinate current application writers without taking over live locks. Browser writes commit on stream close, abort on failure and remove a newly created empty file only while it is still empty. The companion file travels with the entire folder; Git provides history. No account, verification, durable draft recovery, automatic replay or background outbox is required. VS Code authoring, single-file models, other object targets, comment editing/deletion, import/merge/Save As migration and two-way Confluence synchronization remain future scope. External editors, other browser profiles/origins and Git do not share browser Web Locks: conflicting external changes require refresh or recovery rather than silent repair.

label: "View chain shapes table and tree"
action: "Studio shall keep with the view, as one undo step each, a chain of levels among the view's elements (every element for a view that lists none) — the first level's elements of the chosen types as the roots, each next level's elements hanging under an element of the level above along a relation in either direction, along any relation of any type either way, or as the children it contains, a level taking any of several such ways joined with or (needs or requirements; refined into requirements or verified by scenarios) — each level with its own filters by property value, relation, place or text, joined with and or in runs with or, each switchable off and each run showing how many elements come in and go through, and an order by name, type or property, the filters, their suggestions and counts and the order reading an element that stores no value of a property as its type's default, as the card does; offer the types to start with, the relations, any relation (where more than one relation leads on) and containment leading on from the last level or as another way to a level with how many elements each reaches, and the filters that narrow a level (and) or widen its last run (or); and show the result as a tree in the view's table and wiki (an element under several parents shown under each with a +n mark)."
ears_type: "event-driven"
rationale: "Traceability reads as a tree that follows the model's relations: needs, the requirements refined from them, the scenarios verifying those. The chain always works among the view's own elements: it never filters the whole model behind the view's back. A chain written in an older file (a level without ways, an older groupBy) is read as far as it can be, never stopping Studio from opening. The Structure panel that repeated the tree on the right is gone: the table shows it. A filter Repeat is 1 left out the steps that store no repeat, though the card shows them as 1, its default (run 181, 2026-10-23, F-0046).

label: "Compact relation labels"
action: "The canvas shall draw a relation's name at 12 px on at most two lines and its technology at 10 px on one line, in a box at most 160 px wide, cutting longer text with an ellipsis and showing the whole of it while the relation is hovered or selected or an element at one of its ends is selected; and Smart Layout shall leave room for labels of that size."
ears_type: "ubiquitous"
rationale: "At 17 px, larger than the elements' names, and wrapped without limit, long relation names (\"reads and writes the Markdown folder writes .radical/forge-run.json beside\") took four or five lines and covered the diagram. Layout and canvas size labels the same way (relationLabelSize): lines wrap as CSS wraps them, the technology stays on one row, italics are measured as italics, and a label with a wrapped line takes the full width, so the room Smart Layout keeps matches what is drawn. A mean glyph width of 0.56 em wrapped names the canvas draws on one row onto two: 'Identity & AML screening' [REST / JSON] was taken for 108 by 50 px while drawn 156 by 35, and Smart Layout left it over both elements it joins (F-0098, round 193–200, 2026-10-26). Layouts measure a label's text by the UI font's advance table (tableMeasure), never the canvas, so one view gets one layout on any machine and from the MCP server; only the canvas's label placement measures the drawn font. Evidence: packages/layout/src/edgeLabels.ts (RELATION_LABEL_BOX, relationLabelLines, relationLabelSize, tableMeasure), packages/ui/src/components/edges/RelationEdge.tsx, packages/ui/src/index.css (.relation-label-name, .relation-label-tech)"
